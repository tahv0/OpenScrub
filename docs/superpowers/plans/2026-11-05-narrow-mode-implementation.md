Goal: a feature-only PR based on the compound-mask foundation, independent of the still-unvalidated automatic visible-surface backend.

## Global Constraints

- Python >=3.9; full plate mode remains the default. No new model download type, recognition, saved numbers, experimental sources, planning docs, version changes or unrelated refactors.
- `--plate-coverage {full,narrow}` defaults full. `--plate-narrow-margin` defaults 0 source pixels, finite and >=0; CLI, config and web validation must agree. Reopened settings and reports preserve it.
- Reuse the existing SHA-pinned PP-OCRv5 mobile detection model only. No text recognition/dictionary stage. Actual ONNX inference must be exercised on synthetic plates; rejected/missing models fall back visibly to full-plate boxes.
- Keep separate rotated text groups, hyphens and multiple rows; do not hull them into a larger box. Target glyph groups and leave plate background visible. DB restoration is part of localization, distinct from optional margin.
- Explicit margin overrides inherited global pad on successful masks, including zero; retain existing padded full-plate fallback behavior on uncertainty. Never use negative shrinking to obtain narrowness.
- Conservative fallback with stable reason codes for invalid crops, missing/inference-failed models, nonfinite/empty/invalid output, unreliable contrast/polarity, ambiguous rows or residual plausible lettering. A heuristic is not a completeness guarantee; document limits and review prominently.
- Force plate locator and localizer every frame at original resolution independently of scan-speed presets; other categories keep their preset behavior. Do not propagate narrow masks or occlusion exclusions onto unobserved frames. Generated samples use full box fallback.
- Preserve exact per-frame selection in SDR export and paused review through additive source-frame identity or an equivalent tested mechanism, including 120fps. Never paint stale masks while playing: pause to inspect the exact displayed frame. Legacy report behavior stays compatible. Track-based review decisions still affect all samples.
- Reject HDR export when narrow frame-indexed samples are present, including report reload. Matching decoded counts cannot prove mapping between the tonemapped scan copy and original HDR; HDR inputs may use explicit SDR export. Full-plate HDR behavior stays unchanged. This initial feature restriction must be clear in UI/docs/errors.
- Additive Detection fallback metadata and any frame identity roundtrip through reports and surface fallback reason in review. Bbox edits reset geometry as foundation defines.
- Required gates: full pytest suite; full python -m build; actual model inference metrics and synthetic-video render/report inspection; evaluated PAGE JS syntax; real UI interactions/screenshots or clearly reported environment blockers. All examples synthetic.
