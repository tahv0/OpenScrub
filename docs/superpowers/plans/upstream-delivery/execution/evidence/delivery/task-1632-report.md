## Ownership and behavior

Both existing renderer bodies initialize local handles before acquisition and enclose metadata/setup, frame work, final callbacks, stream EOF, waits, diagnostic creation and logging in `try/finally`. Capture, fallback VideoWriter, decoder/encoder children, their actual pipe endpoints and temporary stderr have independent release attempts. Partial setup after decoder creation and before encoder spawn remains covered. Fallback now fails clearly when the actual writer cannot open.

The small shared `_stop_render_children` serves the SDR encoder and HDR decoder/encoder. It first signals all owned running children, then waits up to two seconds each, attempts kill on timeout or another wait error, and waits up to two more seconds. It closes buffered endpoints after that producer/consumer shutdown. If termination/reaping fails and the child remains unconfirmed, the underlying raw stream is closed before attempting buffered close, avoiding a flush into a still-live consumer. Independent cleanup failures are collected rather than preventing later releases. This is a bound on the child-management phase once Python regains control, not interruption of blocked OpenCV/native calls, nor a hard total render deadline.

Normal completion keeps the existing unbounded healthy decoder/encoder waits and EOF flow; successful-control observations include real unbounded waits. Encoder write failure no longer calls an unbounded wait before abort cleanup. It stops the owned children and builds the usual `_ffmpeg_failure` diagnostic while stderr is open, retaining the existing error type, stderr tail and GPU hint. Final nonzero encoder exit also formats diagnostics before stderr closes. Successful encodes now explicitly close stderr even when an observer retains it.

A primary callback/setup/cancellation exception remains the same object and retains its traceback. Python-3.9-compatible `render_cleanup_errors` holds at most eight secondary strings, with each exception message bounded to 300 characters. With no primary exception, a real cleanup/finalization failure raises instead of reporting success. No ExceptionGroup/add_note, generic manager, watchdog, unrelated subprocess refactor, dependency, signature/default/mask/geometry change, or caller lifetime/operation change is introduced.

Closure is separate from deletion. Only the existing recognized cancellation and encoder-write-error paths set the partial-removal flag. Arbitrary setup/frame/finalization errors do not newly unlink `dst`; tests prove previous bytes survive metadata and encoder-spawn failure. Existing cancellation/write-error output deletion remains, and actual FFmpeg writes can already overwrite the final destination. R cannot restore those bytes. P remains necessary for private working stages and prior video/report preservation; G and later C01 composition remain separate.
