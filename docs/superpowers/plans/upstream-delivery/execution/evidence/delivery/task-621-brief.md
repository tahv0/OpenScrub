### What, why and when

Give every operation that reads/writes job files a bounded lifetime. Vault transitions, delete and retention must make admission decisions at the same guarded boundary that excludes conflicting file work. Phase-only checks currently miss saves, thumbnail pre-generation, background tracking and streamed file responses. P06A's atomic rename/vanished-temp tolerance does not solve these races.

This is the lifecycle prerequisite for P06B.2 transactions and cancellation/publication ordering. ### Ownership contract

- Use the existing VAULT_LOCK for short admission/ownership decisions and tree transitions. Ordinary compute, JSON I/O, hashing, decoding and network transfer run outside it. Admission may briefly take JOBS_LOCK in VAULT_LOCK → JOBS_LOCK order; release both before work. Never acquire VAULT_LOCK while holding JOBS_LOCK, and never join a thread or call recursively locking enqueue under shared locks.
- Track store-wide ownership, including intake before a job exists, plus per-job ownership for delete decisions. Validate live job identity and a closed/deleting state under the admission guard. A small private helper with one consistent initialization/release interface is preferable to unrelated counters at every route; it must not become a repository/service framework. Initialize new and both rehydrated-job variants consistently. Keep internal synchronization state out of reports/options/public JSON.
- Ownership starts before the first file access and lasts through the last access/cleanup. An idempotent token/context with explicit transfer to background work or a response is acceptable. Failed admission, thread-start failure, exception, cancellation and duplicate cleanup must not leak or underflow counts. A terminal public phase/status does not mean resources are released.
- Protect intake/new-job/options writes; scan/render queue admission and worker lifetime; tracking admission/computation/publication; thumbnail pre-generation; ordinary report/media/frame/thumbnail reads and writes; and download/report response lifetime. Preserve the existing single tracker policy, without claiming latest-document transaction safety yet. Transfer/reserve background ownership before launching the thread, not when the thread eventually starts. Queued work must remain a busy reason before worker pickup, including cancellation/skip cleanup.
- Preserve the existing immediate retry after cancellation of genuinely queued work. Serialize queued-to-running handoff versus cancellation at the admission boundary: cancellation may retire an unstarted ticket, but a worker-owned ticket retains lifetime until cleanup. A stale queue entry cannot execute or release the reservation of a later retry. Ticket identity/idempotent release here is lifetime bookkeeping, distinct from P06B.2's final report-publication generation.
- Detached JSON response ownership may end after parsing/building its independent response. File streaming ownership must last until the WSGI iterable closes, including early disconnect and error. Do not decrement only in after_request or hold a mutex during the transfer. Preserve Content-Length, Range, filenames, streaming and exact bytes; do not buffer whole videos to simplify lifetime handling.
- Generic server-path routes can also access job files: cover /api/server_video and /api/waveform when the validated canonical target lies under JOBS_DIR, including symlink aliases. Validate the live containing job before stat/read and protect the same canonical target used for I/O. Retain all existing path confinement/permissions, reject stale/deleting/unregistered job targets, and leave allowed unrelated external paths unchanged. Apply the same boundary if intake uses an existing job file as its server source. No global arbitrary-path registry or hard-link/cross-process protection claim.
- A job may retain another job's file as its server source after intake. Derive that physical source's live containing-job dependency during existing admissions and retain a secondary lease only for the operation, deduplicating self/alias ownership. Actual I/O must stay within the validated protected sources, or safely acquire protection before a source change. Protect queued/worker/media/tracker reads as relevant, not only intake. This is active-operation protection, not a persistent retention pin for idle references; no recursive metadata graph or global path registry.
- Delete closes that job's admissions before existing marker/reap/retry behavior. Refuse active work with an honest busy response; reject stale captured job identities after removal. Retry cleanup remains owned relative to vault tree transitions; do not hold global locks across sleeps. Retention uses the same safe deletion boundary, preserving age/marker/retry policy and skipping active jobs.
- Manual lock, auto-lock and shutdown use the same guarded busy definition: queued/running phases plus active owners/background work. Manual lock returns 409 when busy; auto-lock defers. Shutdown has a bounded non-deadlocking busy/failure path and must never encrypt in-use files merely because a timeout elapsed. No worker joins under shared locks; test a signal hook called while the lifecycle lock is already held.
- Close admissions during setup/encrypt/decrypt/rehydrate transitions. Unlock must not advertise readiness until all required decryption and registration completes. Failed transitions remain closed to normal job access until a successful explicit recovery transition; do not let a non-None key alone imply readiness. Retain usable recovery/lock status/error reporting without exposing sensitive paths or keys. Late requests recheck after waiting on the guard, so they cannot write plaintext after lock completes.
- Wire the web tracker callback's existing cancelled() interface to its job Event. Source inspection shows track_manual_region can raise PipelineCancelled before its explicit decoder release; include a narrow engine try/finally owning that capture on success, early return, failed open, cancellation and exception. Preserve matching/output/thresholds and existing fallback/_hold_rest polling cadence. Use focused real synthetic decoder RED→GREEN and unchanged-output evidence. This release-only extension is necessary to establish the new web lifetime boundary; broader tracker polling/algorithm work remains separate.
