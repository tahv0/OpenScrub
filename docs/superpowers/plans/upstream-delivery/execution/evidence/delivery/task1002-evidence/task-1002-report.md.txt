## Optional interfaces and unchanged behavior

`POST /api/jobs/<jid>/track_object` accepts an optional `seed` containing exactly:

```text
{version:1, source_ref,timeline_eq,policy,index,width,height,offset:[ox,oy]}
```

This is the existing sample precondition, without image bytes or row context/baseline. Explicit null/malformed seeds fail rather than taking the legacy path. Consumed strict coordinates/times must be finite and nonboolean. The source-space box must satisfy `0<=x1<x2<=width`, `0<=y1<y2<=height`; the reference must equal `index/fps` and lie inside the chosen valid window. A narrow incompatible window fails without moving the seed or widening the window. Stale source/timeline/index/dimensions/offset refuses before model work. Existing accepted response and running/done/added/error polling remain unchanged.

Both engine interfaces append only keyword-only `strict_seed=None`, preserving every existing positional parameter:

```text
track_manual_region(video,box,t_ref,t0,t1,cb=None,step_frames=2,
                    thr=0.55,scale=0.5,person_det=None,*,strict_seed=None)
_track_person_dense(video,box,t_ref,t0,t1,det,log,step_frames=2,
                    cancelled=None,*,strict_seed=None)
```

The frozen, capture-free `exact_samples.StrictSeed` carries `pixels,source_selection,index,canonical_s,observed_s,fps,count,width,height,policy,tolerance_s`. It validates raw uint8 BGR shape and the existing finite/indexed policy facts. It contains no capture, copied timeline, browser authority, HTTP image or persistent history. The engine checks that its source agrees with the supplied selection. `count` and `tolerance_s` are the concrete facts required by the existing indexed primer.

The shared web adapter `_read_exact_source(selected,index,*,fps,count,tolerance_s)` owns its short open/stamp/read/close boundary and returns `DecodedFrame`. Both exact samples and strict workers use it. Verification captures close before JPEG encoding or strict model resolution; no live web capture transfers into an engine.

Ordinary UI JavaScript/CSS, all nine PAGE composition/input ASTs, `zones_ui` and assets are unchanged. Defaults, dependencies, package declarations, source/report serializers, tracker ordering/search/loss/thresholds and no-seed outputs remain unchanged. The touched person capture owner now also closes on metadata initialization failure; this is a narrow cleanup benefit, not a tracking-algorithm change. No model/training/workbench, source registry, token history, frame digest, whole-input scan, new decoder worker or root production file was added.
