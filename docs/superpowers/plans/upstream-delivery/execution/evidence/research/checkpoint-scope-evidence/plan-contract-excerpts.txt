201: 
202: **What:** Save a consistent partial scan checkpoint, review it using upstream's ordinary UI, and resume the unprocessed suffix while preserving the reviewed prefix.
203: 
204: **Why:** Long scans should not have to restart solely because the user wants to inspect progress. The useful feature does not require learned rescans, sections or a SQLite journal.
205:

Preserve the donor interfaces `with_checkpoint(doc, frame, total, options)`, `validate_resume(doc, source_sha256=None)` and `join_reports(previous, continuation, next_frame, total_frames, completed=False)`. Keep only clean-upstream fields: checkpoint schema/state, first unprocessed `next_frame`, total frames, FPS, input hash and relevant options. The committed prefix is `[0, next_frame)`; continuation timestamps/frame indices and `cum`/`bands` use the original video's coordinates, not an unexplained suffix-relative offset.
