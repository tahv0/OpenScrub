## Donor disposition

`72efeb02:stop_review.py` defines exactly the accepted functions. No product callers exist there. At `ffb4ed9e`, actual callers are `openscrub_web.py:549–615`: load previous raw doc, validate, hash `job.video`, scan from a one-second overlap, serialize a temporary chunk, join, then atomic publish. The earlier engine change is already in that ancestor (`openscrub.py:7056–7075`, `7207–7246`, `8053–8080`). This donor snapshot has the stop Event/callback but the inspected web file contains no stop/resume route; it is not end-to-end feature evidence.

Transfer **interface names/signatures**, separation from Cancel, deep copying, first unprocessed frame, validation before merge, append-only prior rows, fresh suffix track/person ID maps and the principle of finishing postprocessing before replacing the last good report. These are portable concepts; none of the three function bodies should be copied wholesale.

Repair or replace these donor assumptions:

- `with_checkpoint` silently coerces ints (including floats/bools), permits oversized arrays and only requires a truthy hash. `validate_resume` does not enforce supported schema, matching report/meta FPS, all identity components, option equivalence or hash consistency with provenance. Use strict structural/semantic validation with `CheckpointError`, including malformed/missing structures rather than incidental KeyError/TypeError.
- `join_reports` starts from continuation, losing previous unknown top-level and render-state fields. `72efeb02` also loses custom provenance; `0290d5e` repairs provenance wholesale, which can preserve stale output metadata. Start from the complete previous raw document; update only declared owned fields, preserving all other/additive fields.
- It slices new timelines through the **end of their arrays**, rather than the authoritative next frame. It accepts `completed=True` with no advancement or with a cursor below total. It uses a 0.001 FPS tolerance, and no setting validation. It does not reconcile a fresh tracker's scroll origin with earlier content coordinates.
- A one-second overlap is a context choice, not a full detector-state snapshot. PhiMemory, adaptive cadence and temporal grouping restart. The donor clips windows and drops setup track jobs by **reference time**; that can discard the unprocessed suffix of a manual track whose seed is earlier. Preserve earlier rows and either support bounded continuation of such tracks explicitly or refuse that resume case with the checkpoint intact.
- The donor retains all previous audio keys if present, including an empty suggestion list; that can hide a newly computed final audio result. Treat reviewer-owned redactions and machine-generated audio suggestions/transcript separately, with the availability policy below.
- `end_frame is None` is not sufficient proof of full completion: fast-stop can deliberately skip the tail, read failure can end a loop, and metadata count can disagree. No-progress resumption is an unchanged checkpoint, not a new successful completed scan.
- The donor web loop predates the current operation/qgen/report-lock/lifetime contracts; its fixed staging file and unguarded publication cannot replace those contracts.

No training/model-learning/session/section/journal fields, SQLite state, learned-rescan controls, annotation queues, generation framework, training provenance or new root helper belong to this feature. Ordinary selected inference-model identity is needed for compatibility, but custom training is not. P06D's opaque existing additive data still survives: “exclude” means do not introduce, interpret or activate removed feature fields, not silently delete unknown user data from an incoming raw report.

## Recommended portable document contract (P18A)

Keep the accepted call shapes `with_checkpoint(doc, frame, total, options)`, `validate_resume(doc, source_sha256=None)`, and `join_reports(previous, continuation, next_frame, total_frames, completed=False)` in `openscrub_internal/checkpoints.py`. Reuse `reports.atomic_report`; no new dependency or second journal.

1. **Authoritative interval.** `next_frame=b` means all frames `[0,b)` were processed under the saved detection scope, or explicitly skipped as outside it, and fully postprocessed into this committed document. It does not mean every frame had OCR/inference. b is an integer cursor, never detection time, OCR count, decoder-position guess or list length. A paused checkpoint requires `0 < b < N`; complete means all selected work through N is settled. Reject zero/negative/unknown N, non-finite/non-positive FPS and coercible-but-invalid booleans/fractional frame counts.
2. **Consistent arrays.** For a partial document, `len(cum)==len(bands)==b` after finalization; for a completed one both are N. Each element is a finite 2-vector. Deliberately skipped intervals receive explicit zero state when scroll tracking is off. Do not pad unprocessed selected frames or unexpected early EOF and call them complete. Reject mismatched old/meta/render FPS or inconsistent provenance hashes. Strictly validate schema/state before returning metadata; unsupported schema is an actionable fresh-scan requirement.
3. **Metadata.** Keep `stop_review` with schema, paused state, b, N, FPS, `input_sha256` and immutable relevant `options`; extend this schema explicitly to cover source/normalization identity below. The first implemented strict contract may use a new supported schema value and reject the incomplete donor schema rather than guessing missing identity. On complete merge remove only the partial checkpoint marker; retain ordinary source and scan identity in provenance. The helper does not invent completion from a missing marker.
4. **Source identity.** `input_sha256` means the exact scanned canonical timeline file and agrees across checkpoint/report/continuation. Also identify the original media and any separately selected HDR/CFR render participant by hashes, actual FPS, dimensions, total canonical frame count and normalization mode/target/transform version. Paths are locators, not identity. Hash canonical copies after normalization and before publication; revalidate all required participants on resume, before new scan work. Never accept mtime cache identity or a changed original because the scan-copy path still exists. Conservatively reject a changed/missing participant or re-created copy with different bytes; no silent re-normalization into an apparently compatible checkpoint.
5. **Settings identity.** Capture **effective** scan settings once before mutable pixel scaling/pop operations: categories; complete stacked windows/zone/ignore definitions and measured-duration mapping; scan speed/sample/adaptive/stride/scale; thresholds and resolved engine/model content identity; tracking/memory/backtrack/bridge; NER/heuristics/regex/phrase/name/allowlist content; manual setup tracking; relevant audio/normalization settings. Resolve config/defaults and file-backed inputs into canonical values or content hashes. `_settings_dict` is not this contract: it omits dicts and records path strings and unrelated rendering options. Changes to effective scan behavior/source require fresh scan. Explicit render style/encoder/output, transport paths, request Events and resume overlap/cursor are not scan identity; review decisions remain editable. Do not compare current global zones/allowlist as if they were frozen inputs: either reconstruct the saved effective inputs or reject an unavailable/mismatching input.
6. **Merge ownership.** Start from `deepcopy(previous)`. Preserve its entire row list, order and raw row dictionaries exactly: enabled/Keep, disabled and zone-dropped rows, cbox/aoff/poly, dense/track/person, time overrides/last_seen, manual IDs/immutable creation and unknown fields. Preserve unknown top-level/provenance/render-state fields. Replace only the authoritative FPS/arrays, append explicitly eligible suffix rows, advance partial metadata or remove it on verified completion, and update only accurate scan-owned summary/provenance fields. Remove/invalidate stale output path/hash and cached output success on new scan progress. Keep original normalization/source/settings provenance. Do not blindly overwrite it with a newly serialized continuation's paths, timestamp or resume flags. No cross-boundary deduplication/remerge of the old rows and no inheriting Keep decisions by coincidental track IDs.
7. **Forward-only commit.** For partial continuation require `b<e<N`; for completion require `e==N>b`, with explicit engine completion proof. A requested stop before new committed work (`e<=b`) returns the prior document **unchanged**, with no replacement or progress claim; `join_reports` itself rejects no progress. Unexpected early read failure, mismatching counts or finalization/hash/publication failure retains the last good checkpoint. Never complete merely because `completed=True` accompanies a cursor below N.
8. **Suffix interval/IDs.** New automatic output is authoritative only on `[b,e)`, even if overlap/backtracking/smoothing observes earlier frames. Drop wholly earlier output and clip newly appended authority to b/e; never mutate previous rows. Keep timestamps and indices in original video coordinates, with no suffix seconds offset. Remap each distinct non-negative suffix track and person ID into its own fresh namespace greater than every existing ID; preserve -1 and within-suffix grouping, and never match identity across the boundary automatically. Preserve suffix row additive fields and normalized polygon geometry. Check valid finite source time intervals and `last_seen`; under the recommended discrete-authority policy, preserve these original times and intersect activation using the separate bounds rather than silently rewriting them. The exact render-boundary encoding needs the ruling below.

## Engine boundary and coordinate alignment (P18B)

Maintain an explicit whole-frame committed candidate cursor separate from decoder/list lengths. Poll a distinct operation-scoped `stop_requested` before starting the next frame (or latch after the current frame finishes); Cancel remains an exception/abort. Record why the scan loop ended: `requested_checkpoint`, `source_exhausted`, `scope_complete`, or failure. Run normal finalization exactly once on that candidate prefix; allow it to revise ANY still-uncommitted row in the candidate prefix. After publication, that prefix becomes immutable raw review data on later resumes. A later suffix's reverse pass/backtracking/smoothing cannot revise it.

On ordinary EOF, verify cursor/count consistency. On existing track-off fast-stop after the final selected window, explicitly account for the remaining declared out-of-scope frames and build zero tail timeline rows to N; that is `scope_complete`, not interrupted EOF. Close the read-before-scope-gate asymmetry before taking a checkpoint. If early EOF occurs inside still-required work, fail without replacing the prior report. If a Stop request arrives after scanning has already settled every selected frame, finish normally and report “scan completed before stop”; do not fabricate a partial marker at N. If it arrives while a previously fixed partial boundary is being finalized, retain that boundary and finish the existing finalization, never interrupt halfway to publish inconsistent rows.

**Count provenance and EOF limit:** At this pin N comes from `int(cap.get(CAP_PROP_FRAME_COUNT))` (`7360` onward). That is backend/container-reported metadata, not a source-audited decoded count. FPS has a fallback to 30.0, likewise unsuitable as unexplained resume identity. Record where count/FPS came from and whether the canonical timeline has a verified count, rather than promoting reported values to exact facts because the file was hashed. Normalization may supply a validated, hash-bound output count; a cached normalized path alone does not. A partial checkpoint may retain a clearly declared reported N only while the observed boundary is consistent with it, but first-release completion should require an authoritative canonical count/timeline or an actual decoder termination signal that distinguishes clean EOF from failure. The current `cv2.VideoCapture.read()` Boolean does not provide that distinction. `ok=False` alone must therefore never be the proof for `source_exhausted`, including when it happens near the estimated last frame. If N is verified and every index `[0,N)` was actually accounted for, completing the planned range is positive progress evidence; a backend failure before that range ends is an error, and any successfully read unexpected extra frame invalidates the count. For `scope_complete`, logical tail padding is valid only relative to the validated full source timeline and declared out-of-scope tail, not as a way to conceal unknown length. If the implementation cannot establish count/termination confidence with its actual decoder/normalization interface, keep the checkpoint and report inability to verify completion; do not launch an unbounded second full-video pass or fabricate certainty. The precise source of verified canonical counts is an implementation gate, with expected cost and supported formats declared, not a fact established here.

Define an overlap policy in frames (recommended initial context `L=ceil(fps*1 second)` from donor, not a promise of uninterrupted equivalence), `o=max(0,b-L)`. The actual verified reader start is o, not `int(seconds*fps)-1`; using o-1 is also valid only if explicitly included in L. Detector and motion analysis operate only from that declared context onward; no full-prefix inference to restore PhiMemory. A verified seek failure must retain the checkpoint and fail resume or use a documented decode-only transport fallback that does not call detection/motion analysis before o. Reading old compressed keyframe data inside the codec is not a semantic rescan. Clamp deep/onset/merge/context work to this interval. Exact uninterrupted detector output is unsupported; new suffix rows are reviewed afresh.

**Scroll origin is not solved by absolute array indices.** `ScrollTracker` starts from `(0,0)` (`1250–1274`); boxes are in content coordinates and rendering uses `cbox+cum` with drift based on `cum-aoff` (`3993–4006`, `4205–4218`). Recommended origin contract: choose a shared actual overlap frame `k<b` with valid previous and continuation offsets (normally k=o), and let `delta=old_cum[k]-new_cum[k]`. Add delta to new committed `cum[b:e]`; subtract delta from x/y pairs of every new suffix cbox; add delta to each suffix aoff. This preserves `new_cbox+new_cum` and `new_cum-new_aoff`, while putting both segments in the prior report's coordinate origin. Leave previous rows/`cum[:b]` unchanged. Bands are motion deltas used for screen-edge strips, not absolute offsets: splice `old_bands[:b]+new_bands[b:e]`, with no origin translation. Polygons are normalized to cbox: no normalized-coordinate translation. Do not translate unknown geometry formats speculatively.

An alternative is seeding the fresh tracker with the old absolute offset at k before any new rows are formed; it must prove the same invariants. Constant-origin rebasing does **not** restore historical tracker keyframes, memory, cadence or identity state. It does not establish bitwise equality with a continuous scan or correct an arbitrary detection failure. Require a nonzero-scroll render/geometry regression plus a review-extended old row that crosses b. Unknown continuation geometry needing a transform must be explicitly supported or refused; never drop it. If no common valid frame can be established, refuse this resume attempt.

**Setup manual tracks:** Do not filter by seed reference time as donor does. A bounded continuation can use the last committed sample/box at b-1 to seed the remaining requested interval, preserving the old manual rows/IDs and allocating a fresh suffix track. That is additional tracking work requiring its own actual-interface regression. Smallest first delivery policy: reject resume of a setup track that spans b and cannot be safely re-seeded with existing tracking interfaces; explain fresh scan while keeping the checkpoint reviewable. Ordinary saved manual annotations, polygons and tracked rows must always survive. Never silently claim those future tracking requests completed.

**Audio:** Preserve previous `audio_redactions` exactly, including empty lists and additive span fields. First partial scan may defer the existing whole-file transcription and must state audio scan incomplete. Do not publish an empty suggestions/transcript key as a fake completed result. At final completion, the existing full-file audio interface may run once; merge new suggestions/transcript only if those keys were absent/deferred, preserving any existing raw audio metadata. Never reapply `audio_pii_apply` over a saved reviewer choice on resume. Whole-file audio inference is an explicitly documented exception to suffix-only **visual** scanning, not evidence of audio suffix support. Supporting partial audio would be separate work. **The earlier partial-render blocking recommendation below is superseded by the labelled policy amendment at the end of this report.**

## Operation/state/publication controls (P18C)

Use one report file plus current qgen/operation/lifetime mechanisms; no persisted running operation, generation framework or second transaction log. Attach a separate Stop Event to the **captured operation**, not merely the job dict. Repeated Stop on that attempt is idempotent; a delayed Stop request cannot affect its retry/resume replacement. New operation admission allocates fresh Events, following existing capture-before-wait Cancel semantics.

| Request/state | Recommended result |
| --- | --- |
| Stop during active main scan | Signal graceful stop for captured operation; show stop pending/finalizing. Do not advertise paused until postprocessing and atomic report replacement succeed. |
| Stop during scan finalization | If boundary already fixed, join that pending stop. If full source/scope already complete, normal complete review wins. Do not restart or shorten finalization. |
| Stop while queued, queued_render, rendering, failed, idle review/done | Explicit 409/not-applicable (a replay for the same committed stop may return already-paused success). Cancel remains the action for queued/render work. No queue consumption solely to create a zero-progress checkpoint. |
| Cancel after Stop request, before checkpoint publication | Captured cancel invalidates the attempt; do not publish. Existing prior checkpoint remains available for later explicit Resume once cleanup finishes. |
| Cancel waits while publication owns report lock | Either publication wins first, then cancel invalidates; or cancel wins and publication refuses. No publication from the captured cancelled operation after Cancel acknowledgement. Never mutate a newer operation. |
| Resume paused checkpoint | Admit file/source lifetime, capture source/identity, load and validate latest raw checkpoint under report lock, reserve action=`resume` with fresh operation/qgen, then compute/hash outside the lock. Edits/tracking/render conflict while queued/running/cleaning, per current gate. |
| Resume failed/cancelled attempt retaining a valid prior checkpoint | Explicit Resume may use that durable checkpoint after cleanup; Retry keeps existing fresh-scan semantics. Do not automatically choose resume because a report file happens to exist. |
| Duplicate/concurrent Resume | One admission wins, other gets busy; no duplicate suffix append. Use operation identity and existing active owner, no new revision counter. |
| Process dies during continuation/finalization | Reopen last atomic report as paused; staged transient data is ignored/cleaned by existing temp convention. A complete verified report reopens review; partial marker always overrides stale output existence. |
| Render partial report | **Superseded proposal:** the original recommendation refused export until resume completed. The policy amendment below instead permits explicit rendering of current choices with honestly unhandled remainder; correctness errors remain actionable. |

For resume, preserve stable job identity, selected original/scan/HDR source leases and latest document ownership. The source identity hash/check may be large and must run outside report lock while active admission blocks mutations. Recheck exact operation and source selection on final publication. External filesystem mutation is outside in-process locks: hash identity does not create a content snapshot; document that sources must remain stable during an attempt, and recheck before commit if claiming detection of mid-attempt edits.

Prepare the finalized candidate outside the report transaction. Under stable `files.report_lock`: verify same live job, nonclosed files, same operation/qgen, no cancel, expected original checkpoint boundary; load the latest committed raw report if needed; merge only against that base; call existing atomic publisher; set matching partial/complete job state/stats/progress/output invalidation before releasing. Keep no file I/O that admits/releases leases inside this lock. Atomic JSON serialization/fsync/replace is the already-defined final publication I/O, not an excuse to hold the lock through inference, source hashing, normalization or a large copy. No temp fixed `.scan-chunk.json` is needed if report construction returns a document. Active ownership remains through actual thumbnail/worker cleanup as existing interfaces require; edits become legal only after that cleanup.

Publication failure must not set paused or advance b; the previous report stays valid and error is visible. A later Cancel may leave an already committed checkpoint on disk, but cannot cause a late old publish. A fresh Retry does not destroy that previous report until a new authorized publication succeeds; if it does publish, old resume context is superseded rather than merged into the new scan. Cancellation of queued work must preserve immediate retry and release only the captured queued leases. Deletion/retention/vault rules continue using current owners; pending graceful stop is active work, not a release of protection.

CLI controls must be explicit and use the same helper/boundary logic. Smallest portable proposed surface: a deliberate absolute checkpoint frame trigger plus `--resume-report PATH` (actual names belong in P18C), with the resumable report as the durable artifact. A request/callback API permits interactive callers to request Stop. Do not silently reinterpret ordinary Ctrl-C cancellation as successful checkpointing. If on-demand CLI terminal signaling is a required first-release UX, rule on its trigger before implementation rather than hiding platform-specific signal handling in P18A. CLI simultaneous writers remain unsupported unless an existing coordination contract is added separately; web locks do not coordinate processes.

## Supervisor ruling before implementation: effective frame authority

The required invariant is that newly appended suffix detections cannot activate on committed frames `<b`, including 120 FPS, serialization/reopen and ordinary time/geometry edits. Preserve original detector times; do not silently shift them by 0.01 and claim they are unchanged. Two narrow choices:

| Choice | Advantages | Required costs/limits |
| --- | --- | --- |
| Explicit optional frame authority on newly generated rows (recommended) | Keeps original times and exact `[b,e)` ownership, independent of FPS, floating-point tolerance and future time edits. Decoder/renderer intersects ordinary time activity with the recorded authority interval. Old legacy rows retain current behavior. | One small clean row contract, e.g. `scan_frame_start`/exclusive `scan_frame_end`, carried through raw merge, `_decode_report`, render and edit semantics; no journal or object-generation system. Newly generated automatic checkpoint rows must receive bounds before first publication, not retroactively rewrite old reviewed rows. Manual user regions need an explicit rule to permit deliberate future spans while preventing automatic overlap output from expanding into protected prefix. |
| Boundary-safe timestamp encoding | Avoids row fields and can stay within current render activation equation. | Must encode away the existing ±0.01 activation slack, preserve positive tiny spans and compensate binary float/JSON roundtrip. This changes persisted detector timestamps; an ordinary editor time save can undo it. Would need separate original times/authority semantics or editor changes, reducing its apparent simplicity. A plain `max(t_start,b/fps)` demonstrably does not establish the contract. |

The concrete **recommended, not yet approved** row contract is a paired `scan_frame_start` and `scan_frame_end`, strictly integer `0 <= start < end <= N`, with end exclusive. Both absent means ordinary legacy time activation; one missing or malformed means reject a checkpoint/resume document rather than silently ignore authority. Newly generated first-checkpoint rows receive authority `[0,b)`; newly appended rows receive `[b,e)`, intersected with their original time activity. This includes generated setup-tracking/zone-dropped rows; it does not retroactively alter any previous raw row. Keep the bounds after completed resume and subsequent render/reopen, since removing them would reactivate overlap/hold samples outside the original segment. Original `t_start`, `t_end`, `last_seen` and normalized geometry retain their ordinary meaning.

The exact paths that would honor this proposal are bounded:

- `Detection` (`openscrub.py:733`) gains optional paired fields; `_decode_report` (`6360–6386`) validates/carries them into the enabled subset. Fresh scan serialization adds them only when the checkpoint feature uses authority; preserve legacy output shape when absent. Existing raw `source_report` publication keeps them without rebuilding rows. `apply_coverage` (`3747` onward) copies detections and must retain fields. No alternate geometry/render algorithm is required.
- `render_hdr` and `render` activity filters (`3999`, `4210`) intersect existing time activity with `start <= idx < end` using the actual original frame index, before dense deduplication. Use idx even for trimmed output; do not derive authority from rounded display times. CPU/SDR and HDR paths need identical tests. Other callers consuming `Detection` objects retain legacy behavior for absent bounds.
- `job_boxes_at` (`openscrub_web.py:1582–1609`) uses the same authority for the actual requested original source frame and returns bounds additively with row data; `job_detframe`, thumbnail reference selection and pre-generation must clamp reference frames to the row's valid active authority. The review detections projection (`1542–1558`) may expose bounds additively for faithful display; it must not round or rewrite the raw authority or source times. Existing raw report/download routes preserve them.
- `job_save_edits` explicit `time_overrides` (`1738–1749`) is intentional human ownership: an accepted time edit may remove the pair for **that row only**, making its requested new time interval ordinary user-authored coverage. This deliberate action can extend coverage across a prior scan segment. Enabled/Keep toggles, box/polygon edits, sparse untouched values and manual replay must never clear bounds. The server must reject malformed authority supplied as arbitrary client data rather than letting clients accidentally reinterpret it. Human-created manual regions and review-stage Track object additions retain ordinary requested spans without automatic scan authority.
- The existing JS `beFilter`, `beApplyTimes`, `beShowTimes` paths (`3094–3106`, `3141–3157`) need the same distinction: persisted bounds apply until the user deliberately submits a time edit; a pending explicit time edit previews that deliberate new interval, without silently changing unrelated rows. P07 acknowledgement/retry must retain that intent and clear only the acknowledged draft. No ID-to-row or journal protocol is added.
- `job_detections` currently returns `duration=len(cum)/fps` (`1555–1557`). A partial report must expose full canonical source duration `N/fps` plus a separate committed boundary, so fraction-based review controls still address original media. A request for overlay state outside committed frames must report unavailable/unprocessed rather than use the last offset through `min(index,len(cum)-1)` and imply a scanned tail. This is an inspection-state correction, not a new full-media cache.

Older versions can preserve these fields as opaque data but render without honoring them; therefore authority-bearing checkpoints require an implementation version that supports this row contract. State that compatibility limit explicitly in documentation/validation. Do not describe an older renderer as safe simply because it can parse the JSON. Tests must prove deliberate manual time edits remain user data and all other edits/replays preserve authority. P18A can settle identity/raw preservation independently; final suffix clipping/render tests and P18B/C implementation must follow the supervisor's recorded ruling. ## Policy amendment: explicitly render current choices from a partial checkpoint

**Amendment requested by the supervisor after initial review; source-only recommendation, no runtime work.** This section supersedes the earlier blanket render/export completeness gate and its test obligation. The supervisor has **provisionally selected paired exclusive frame bounds** over biased timestamps. The following partial-render semantics are the recommended final policy; they do not change the accepted feature into a requirement to finish handling the remainder.

An explicit user action may render/export the current valid report, including a partial checkpoint. Stop must never automatically enqueue `skip_review` rendering: it ends in review after publication/cleanup. The UI and CLI show the full canonical source timeline, the known processed boundary `[0,b)`, any count uncertainty and audio-incomplete status. A successful explicit partial render means the requested current choices were rendered; it does not change b, remove `stop_review`, claim the suffix scanned, complete audio inference or disable Resume. Show the result as a partial render with scan still paused, even when a valid output file exists. Report/output provenance may identify that output accurately while retaining the partial coverage marker. Restart derives resumability from the validated report, not `output.mp4` existence.

Unprocessed frames may pass through unmodified wherever the user has no explicit applicable choice. Do not automatically mute their audio, add bands, extend detector hold, freeze the last detector box, infer object motion, scan the suffix or require the user to complete review as a condition of export. Saved explicit audio redaction/mute-lane/trim choices remain ordinary user-owned rendering inputs and may apply anywhere on the original source timeline. Audio-incomplete describes unfinished machine analysis, not invalidity of deliberate audio choices.

### Why existing clamping is insufficient

Both renderers read `cum[min(idx,len(cum)-1)]` and `bands[min(idx,len(bands)-1)]` (`openscrub.py:3996,4019,4207,4253` vicinity). After b this repeats the last cumulative offset **and** the last safety-strip motion vector. A nonzero final band can therefore redact an entire unprocessed tail despite no new motion evidence. The last cumulative offset can make content-coordinate choices look stable while their required future motion is unknown. Neither is evidence that the tail was processed. `job_save_edits` also uses this clamp when converting a submitted manual screen box at `t_ref` (`openscrub_web.py:1762–1774`), so merely accepting a future manual row does not establish its coordinate semantics.

For explicit partial rendering, apply machine arrays only on their validated processed domain. For `idx>=b`, automatic bands are absent/zero **for rendering only**; do not pad saved `bands` to N or alter its committed prefix. An automatic row generated by the checkpoint scan retains its paired authority and cannot activate after that row's segment end, even if `t_end` contains a hold/grace tail. A previously appended suffix row cannot activate before its segment start. Intersect authority with original time activation in both renderers and `boxes_at`. Retain these bounds after completion and render/reopen. Do not infer future `cum` values from the final sample or mutate old arrays/rows to make the render appear complete.

### Explicit geometry in an unprocessed span

Future manual/redaction choices are valid when their screen geometry is defined without unavailable automatic motion. The narrow render contract is:

- In `[0,b)`, ordinary content coordinates use the committed `cum` exactly as before. Valid user-owned screen-coordinate rows can also render there without motion inference.
- At/after b, explicit **screen-fixed manual rectangles/polygons**, or explicit per-sample tracked screen geometry with a declared sample time span, can render on their authored spans. Use their authored screen box and normalized polygon directly, with ordinary requested padding; do not add drift expansion from nonexistent future motion. A dense tracked sample is honored only for its own declared span, not frozen for the entire remainder.
- A legacy content-coordinate manual row spanning beyond b needs a future cumulative offset that this checkpoint does not have. Do not silently reinterpret it as screen-fixed or skip it. Return a targeted geometry error identifying the affected row/span, with the concrete remedy of an explicit screen-geometry choice or an edited span within known geometry. This is an unsupported-coordinate correctness condition, not a ban on partial rendering. A valid report with no such unresolved enabled choice can render immediately.
- An explicit time edit may remove that row's automatic authority, as already proposed, because it is human coverage intent. That action does **not** magically supply missing geometry. A retimed machine-category row outside b needs explicitly authored screen geometry too; neither its category nor the fact that its bounds were removed authorizes automatic motion or a silently frozen detector result. Enabled/Keep/box changes and manual-ID replay do not remove bounds.

The smallest proposed representation, if this screen path is needed for initial manual-after-b support, is an optional clean row field such as `geometry_space: "screen"`; default absence retains existing content-coordinate semantics. In the screen case the row's authored screen rectangle can be represented by `cbox+aoff`, while the renderer bypasses global `cum` and automatic drift. This preserves an explicitly converted legacy row's raw cbox/aoff/poly; the conversion field is added only by a deliberate geometry action. Do not add the field automatically to every old manual row. For a **new** screen-space manual creation, normalize cbox to the submitted screen box and aoff to zero, independent of `cum`, so `manual_creation` and lost-response replay remain stable after resume fills future offsets. Include the coordinate-space intent in the new manual-creation compatibility rules, outside or additively beside the existing immutable record as explicitly specified before implementation; never overwrite a prior immutable `manual_creation` to make a retry match. Existing prefix manual creations keep their original representation unchanged. A legacy after-b creation that used clamped offsets needs an explicit supported conversion/replay policy, not reconstruction against newer motion.

This optional geometry field is a proposed minimal data contract, not authorization for a new tracking mode. Existing user-requested tracking may supply per-sample screen boxes; P18 does not run a new tracker to invent them. If the first delivery does not implement an explicit screen-coordinate path, its limit is the concrete unsupported enabled content-coordinate choice after b, not partial status or an otherwise unhandled suffix. Do not silently drop that choice to complete a render.

### Compatibility, preservation and focused acceptance checks

`scan_frame_start` and exclusive `scan_frame_end` remain optional **paired** strict integers on newly generated checkpoint rows. They govern automatic temporal authority and preserve source timestamps. The proposed optional screen-geometry field governs only an explicitly authored coordinate interpretation. Raw previous row dictionaries/order, manual IDs, immutable creation snapshots, audio fields and unknown additive fields survive join/render unchanged unless the user deliberately edits that specific choice. Rendering builds a temporary enabled projection; it does not rewrite or materialize the unprocessed timeline. Do not copy a last offset into report arrays, inject rows, drop disabled rows, overwrite an old polygon or update checkpoint progress as a side effect of export.

Current older renderers ignore both proposed row authority and screen-coordinate semantics. They can preserve unknown fields as data but cannot be claimed compatible for correct rendering. Document the minimum supported feature schema/version and reject unsupported/malformed authority/geometry interpretation in participating entry points. Valid legacy ordinary reports continue existing behavior; checkpoint-schema validation and exact source/normalization identity apply to partial rendering just as resume. A changed original/scan/HDR participant, incompatible timeline/FPS/dimensions, malformed arrays/bounds, unknown coordinate semantics or invalid geometry remains a legitimate correctness failure. Unknown raw additive metadata alone is not such a failure. Do not silently re-normalize a different source or use the existing render-only hash **warning** (`openscrub.py:8564–8567`) as sufficient checkpoint compatibility validation.

Replace the earlier gate test with these future tests: explicit web/CLI partial render succeeds while b and audio-incomplete status remain; Stop never autoqueues render; unchosen unprocessed video/audio remain unhandled; nonzero final bands do not repeat after b; bounded machine rows do not leak at either side at 120 FPS; valid screen-authored manual/audio choices beyond b are honored without invented motion; unresolved enabled content-coordinate geometry produces the targeted error and preserves report/output publication rules; rendered report retains every raw row/manual replay identity/partial marker; restart still offers Resume; and deliberate screen creation/replay before and after resumed timeline growth does not reset later edits or alter immutable creation.
