## Backend sample: selected minimal supported contract

Use one small indexed-reader primitive shared by the web resolver and optional strict tracker launch, for example `read_indexed_capture(cap, index, policy) -> DecodedFrame`. Its caller owns/open/releases the capture; after success the capture is immediately after the verified index. A source-path wrapper may open it and release in `finally` for detached HTTP samples. `DecodedFrame` carries raw pixels, verified index, finite observed presentation seconds and dimensions; it owns no Flask globals/lifetimes. A private `openscrub_internal/exact_samples.py` is justified only if this shared reader/finite validation avoids divergent web/engine implementations. Source selection/ownership remains in `_JobFiles` and web adapters. This is not another tracker or a decode-worker framework.

The initial supported policy must declare all of the following:

- One unambiguous selected video stream; a zero-origin CFR scan timeline whose fps/count/source-to-report relation is established by the managed scan/normalization path. A matching pair of advertised frame rates alone does not establish CFR. Native VFR/`--no-vfr-fix` and unproved original-to-normalized/HDR relations are unavailable for exact editing.
- A validated OpenCV FFmpeg decode policy with deterministic same-source/index decoding and usable post-read presentation time. The prior H.264/native-CFR/normalized-CFR observations support feasibility only for their recorded build/fixtures. Unknown backend/time-origin/rotation/stream behavior stays unsupported until its owning acceptance exists. Zero observed time is valid at index zero; a backend returning zero at every nonzero index is not valid.
- Finite positive fps; nonempty `cum` with finite two-value offsets and `N=len(cum)` defining the report scan timeline. Expected positive finite integral source dimensions and explicit identity spatial orientation/transform. The decoded nonempty array must match these dimensions. Decoder frame count is a consistency hint; a disagreeing known count must not silently truncate the report. Do not derive `N` merely from container duration.
- A finite non-boolean numeric requested time in `0 <= t <= D`, where `D=N/fps` is finite. Resolve **once**: `i=min(floor(t*fps),N-1)`. Carry `i` as an integer; never convert it to seconds and back to choose a frame. The whole final interval `[(N-1)/fps,D]`, including exact `D`, denotes the last sample; arbitrary out-of-range requests are rejected.

Canonical scan time is `i/fps`; offsets are exactly `cum[i]`; visibility uses the renderer's existing `t_start-.01 <= canonical_s <= t_end+.01` rule. Preserve stored interval endpoints, rather than rounding them for the editor. `requested_s`, `canonical_s`, and `observed_s` remain distinct. Do not invent integer PTS/time base. The simplest first zero-origin policy checks observed post-read seconds against canonical seconds with a named, tested precision bound strictly smaller than half a frame interval; **the final bound remains a supervisor/implementation acceptance decision**. The study's 1µs comparison tolerance was an evidence-display accommodation, not an adopted production tolerance. No tolerance may admit an adjacent sample or the existing ±1-frame fallback.

Open the admitted source, compare opened/path identity before and after decode, set the integer index, read once, validate observed evidence/dimensions, encode successfully, and revalidate the selected report/source context before accepting detached bytes. `cap.set` success/position counters alone are insufficient. Release capture/open handles in `finally`, then request ownership through existing response cleanup. No sequential prefix verification scan, full-source hash, full-report identity hash, alternate FFmpeg extractor, persistent PTS index, workers, retries/deadlines framework or long reader gate is part of this slice.

Proposed wire shape (spellings remain private/provisional until implementation):

```text
GET /api/jobs/<jid>/edit_sample?t=<finite seconds>
200 private, no-store JSON {
  version: 1,
  sample: {
    source_ref, timeline_eq, policy: "cfr-index-v1",
    index, requested_s, canonical_s, observed_s,
    width, height, stream: 0, origin: [0,0], offset: [ox,oy]
  },
  image: {mime: "image/jpeg", base64: "..."},
  boxes: [{i, category, text, enabled, t_start, t_end,
           box: [source_x1,source_y1,source_x2,source_y2], row_eq}]
}
```

One encoded image plus geometry/offsets in one response is smaller than a separately fetched image token protocol. Full-frame origin `[0,0]` avoids a crop transform API. `boxes` includes disabled active raw rows, matching current `all=1`, and retains concrete raw indices; group representatives cannot silently substitute for them. `source_ref` is an opaque current observed-source reference owned by the existing job state, not a source digest or permanent identity. `timeline_eq`/`row_eq` are bounded equality evidence described below, not assertions that a client is authenticated or genuinely inspected pixels. No separate sample ID is required: `(source_ref,timeline_eq,index,policy,width,height)` identifies the request-local sample under the declared policy. The JPEG is a lossy display of that decoded sample; it does not imply browser RGB bytes equal the raw BGR array.

Return JSON errors with stable small codes and no usable exact image: `400 invalid_sample_request` for malformed/nonfinite/out-of-domain time; `404` for missing job/report/source; `409 source_report_pending` or `409 sample_conflict` for detected changed selection/incarnation/timeline during the request; `422 exact_sample_unavailable` for unsupported timing/backend/transform, incoherent metadata, EOF/mismatched observed sample/dimensions. An encoder exception may be `500 sample_encode_failed`. Ordinary authentication/vault/deleting/operation gates retain their current status codes. The UI clears readiness on every error; no walk-back is success. A current error must not return a stale cached sample. These statuses need no capability discovery endpoint.

## One observed-source owner, two freshness projections

Extend the existing `_JobFiles` state with only current metadata: an opaque per-live-incarnation identity, current managed source epoch/descriptor, current report publication epoch, and coherent/pending source-report selection state. The source descriptor contains canonical selected scan path, opened file stamp `(device,file-id/inode,size,mtime_ns,ctime_ns where reliable)`, stream/dimension/orientation/normalization policy. File stamps describe **observed** identity, not immutable bytes. The browser needs only opaque `source_ref`; do not expose internal paths merely to implement equality. Reuse a current descriptor when its actual inputs match. Concurrent discovery must converge on it, not mint a new source reference on every read.

Use a small API on this owner, with names illustrative:

```text
prepare_source(job, owner, candidate_path) -> PreparedSource  # outside report_lock
select_source_locked(job, prepared, report_fence) -> SourceSelection
observe_open_source(selection) -> OpenedSource              # outside lock
source_matches_locked(job, selection, opened_stamp) -> bool
report_committed_locked(job, report_stamp, scan_pair_pending=False)
source_committed_locked(job, prepared, matching_report_fence)
```

`prepare_source` performs existing VAULT admission/related-job reservation **before** following/statting/opening a source. `select`/`commit` merely inspect already-owned preparations under `report_lock`; never acquire VAULT there. Source/report open/read/parse/decode and lease release remain outside that lock for sample/P08 selection. Revalidate current job object, closed flag, relevant operation and observed path/opened stamps on final accept. The existing save's latest-document read is already inside its transaction; do not turn this handoff into a general transaction-I/O refactor.

| Consumer | Equality/invalidation boundary |
|---|---|
| P08A thumbnails/lightbox | Derive its opaque `V` from the common source descriptor **plus** whole-report publication/observed report stamp, operation/incarnation and recipe. Any successful managed report publication can retire `V`, including choices/audio. Preserve the amended no-whole-input-hash design and separate per-row browser rebinding evidence. |
| Exact sample request | Snapshot coherent report/source selection and parse private raw report once. Resolve integer, timeline projection and active rows. After decode, ensure the consumed projection is still current. If only report epoch/stamp changed, one bounded fresh document comparison may accept equal consumed facts; otherwise return409. A simpler bounded409/retry on an overlapping publication is acceptable for the request, but **that epoch is never a draft-save precondition**. |
| Geometry draft / strict seed | Compare current source reference, timeline equality and its actual target row equality. Report epoch, output hash/path, enabled choices and audio are excluded. Changes in unrelated rows do not affect the target row's equality. A source-only change does invalidate the sample even when the report text is identical. |
| P16C output publication/read | Its output path/publication epoch remains a separate owner. Exact **input** samples never read `job.output`, accept `src=output`, reuse output-read epochs or treat a new render file as a new scan sample. |

`timeline_eq` is a deterministic digest of a strictly canonical finite coordinate projection: policy/recipe version, fps, `N`, ordered full `cum`, selected source stream/dimensions/orientation and declared scan-source relation. It excludes `bands` (not the box coordinate transform), output/provenance timestamps/settings unrelated to that relation, audio and every enabled flag. Hash the projection while the necessary parsed timeline is traversed; this is not another full-report read/hash and not a retained report cache. Work is O(N), not constant; measure introduced cost during implementation. A cached small digest may be reused for an established coherent timeline, but its validity must be established across report publications by actual projection equality, not by assuming all saves are harmless. A whole-report stamp alone cannot distinguish audio changes from coordinate changes.

`row_eq` is a deterministic digest of the **target raw row excluding only its output choice `enabled`**, using canonical strict JSON equality, at the returned raw index. This includes `category,cbox,aoff,t_start,t_end,last_seen,poly,dense,track,person`, text/confidence/zone/manual identity/immutable creation where present, and opaque additive row fields. This slightly conservative row-local choice avoids inventing an incomplete geometry whitelist or discarding identity hints. Future row-local output-choice fields may be excluded only by an explicit contract amendment. Compare current row at the same index; changed cbox/anchor/span/group/category or a different reordered row rejects. Never search for a similar row and retarget the edit. A semantically identical row exchanged with an exactly identical row except `enabled` is indistinguishable without permanent row IDs and has the same coordinate/creation meaning. This contract rejects **distinguishable** replacements/reorders; it does not claim stable logical row identity. Strict rejection of invisible identical-row swaps would require a separately authorized stable-row schema, not a sample token/history ledger. Different enabled values remain merged from latest JSON.

## Optional draft preconditions in the existing save transaction

Preserve the existing payload fields. Add optional `geometry_preconditions` keyed by raw row index, shared by that row's submitted `box_overrides` and/or `time_overrides`:

```text
{version:1, source_ref, timeline_eq, policy, index, width, height,

```

New manual entries may carry the same optional `sample_precondition` without `row_eq`, because no existing target row exists. They retain current `manual_id,t_start,t_end,t_ref,screen_box`; strict `t_ref` is canonical sample time. No field is persisted in the report simply because it was a transient precondition. `manual_creation` retains exactly its existing four immutable effective fields (`t_start,t_end,cbox,aoff`), separate list values and integer content-box normalization. A request-supplied `manual_creation` is still not an authority. Missing optional preconditions preserve legacy semantics; invalid explicitly supplied new preconditions reject rather than quietly taking the legacy path.

Validate in this order, before the single publication:

1. Parse/shape-check deltas and optional preconditions, including bounded field sizes, nonboolean finite numbers/integer indices and supported version. Do not open/decode/validate the sample merely because a manual entry supplied old evidence. A choices/audio-only save needs no new source admission.
2. Take the existing `report_lock`, run `_edit_gate`, load the **latest raw** document, and build the current manual-ID lookup before mutating its rows. Check against this baseline, not against a document already modified by another delta in this request.
3. For an identified manual entry with strict evidence, compute candidate immutable creation using its finite **captured offset** and submitted screen box/times with existing integer conversion; this is arithmetic/shape validation, not current-source validation. If exactly one stored `manual_id` has valid identical `manual_creation`, treat this addition as already published and skip new sample freshness. Duplicate/invalid stored creation or different candidate remains409. Do not compare against its mutable current cbox/time/enabled. For a legacy manual entry retain the existing latest-cum normalization/replay behavior unchanged. Do not globally require a current exact decoder/source merely to acknowledge an identical stored manual addition.
4. If genuinely new strict additions/indexed geometry still need source ownership not yet admitted, exit the lock **without publishing**, prepare that source via P06 outside the lock, then reenter and repeat `_edit_gate`, latest-document loading and replay classification before validation. This two-phase case is necessary because a replay-only request must not fail on an unavailable new source, and report→VAULT acquisition is forbidden. Revalidate the prepared source/operation on reentry; release preparations outside the transaction. For each genuinely new strict manual addition and each strict indexed geometry delta, compare current source/timeline/policy/dimensions; check selected index and canonical-time resolution, `offset == current cum[index]`, and target `row_eq` at the submitted raw index. Use current server facts to compute/validate content coordinates. For strict additions validate its window/reference and creation shape/domain. A mismatch is JSON409 and publishes **none** of the combined geometry/choices/audio edits. Unrelated choices/audio in latest report remain legal and are retained. Already-published replay exemption applies only to that addition, not to other stale deltas in the same request.
5. Apply validated geometry/times, new additions and choices/audio to latest raw JSON; preserve unknown/top-level/row fields, disabled rows and immutable creation. Publish once atomically, then notify report epoch. No source/hash/decode is required for ordinary enabled/audio deltas without new preconditions.

An exact geometry retry after an uncertain acknowledgement can succeed without republishing its target if the **current source/timeline still matches**, the same raw row's non-target projection matches the captured evidence, and every submitted target field already equals the intended replacement. Otherwise409. This narrowly optional idempotence rule needs separate baseline/target equality (for example fixed-size `row_context_eq` excluding only the explicitly replaced `cbox` and/or span/derived `last_seen` fields, alongside `row_eq`). If this complicates the first backend diff, defer automatic indexed-geometry replay success and retain the draft on409; **do not weaken source matching or P07b manual replay**. This is a remaining supervisor choice, not permission to accept arbitrary row changes.

Capture a draft's precondition when it first becomes a pending mutation, not at Save and not on every scrub. Re-editing the same pending row retains its original server baseline; scrubbing onto a new exact sample is not permission to rebase stale geometry. Couple each map value and precondition in the deep P07a snapshot. Acknowledgement clears the paired draft only when its current value equals the submitted value; toggled-away-and-back equal values may clear, newer different values survive. For strict indexed submissions, extend the successful existing response with `geometry_rows: {index: {row_eq, ...adopted_context_evidence}}` computed from the committed row. Newer different geometry advances to **that acknowledged baseline** without changing its pending value; update only the owning draft whose previous baseline was the submitted one. An uncertain failed response cannot safely invent a new baseline. This is per-pending-draft bookkeeping, not a persistent action counter/history. If a strict409 cannot be reconciled, retain pending edits and require explicit reinspection/reapplication; never silently drop/rebase them.

Pure Remove/Blur/Keep and audio are output choices and need no image sample. Time edits of a selected geometry row consume its row/timeline precondition. Do not introduce a blanket report revision gate. Legacy in-page drafts created before the UI migration cannot be granted synthetic exact evidence: preserve them through the existing legacy optional path for that page/acknowledgement, or explicitly retain them for user reinspection; do not discard them on migration/remount.

### One row context plus explicit baseline targets

|---|---|---|---|

Successful strict saves return only submitted rows in `geometry_rows`, each with the **committed** `row_context_eq` and complete `{cbox,span}` baseline plus the unchanged adopted source/timeline/sample context.
