## Epochs and source lifetime must remain separate

1. **Live incarnation and operation.** `_JobFiles` is initialized before registry insertion for new jobs (`web:495–521` / combined `511–537`) and reconstructed in rehydration (`4445–4546` / `5567–5690`). A fresh live incarnation retires old source references. Operation Event identity fences queued/scan/track work; it is not a report revision or durable identity. Retrying a job retains the combined JobLog store/epoch, which must never stand in for incarnation.
2. **Observed selected input source.** Current leases pin canonical path and containing-job lifetime. They do not pin immutable bytes or prove that new report geometry describes the path. Descriptor discovery must converge under existing owner, record reliable opened/path stamps and small stream/dimension/orientation/relation facts, and revalidate before detached acceptance. Source A→B→A and observed replacement retire the previous current reference. Normalization provenance path, scan input hash and an arbitrary token are distinct facts. OpenCV opens by pathname; a separately opened descriptor does not eliminate its pathname-open race. The adopted managed/observed-file limit remains explicit.
3. **Committed report epoch.** Neither pin has the adopted success-only managed report epoch. Standalone notifications must follow successful atomic replacement at scan/render callback, save and tracker writers. No-op ACK may leave this epoch unchanged. Failed publication leaves the committed pair unchanged. Report epoch/opened report stamp can guard a request snapshot or future thumbnail generation; geometry save freshness uses source/timeline/target row instead.
4. **Combined `output_epoch` is an attempted mutation fence.** `_publish_job_report_locked` increments it **before** `os.replace`, so replacement failure can advance it without publication. `publish_render` passes an incrementer as `_RenderDelivery.commit(before_mutation=...)`; it runs before destination mutations and rollback restoration. Thus it can advance multiple times during a successful pair commit or failed/rolled-back delivery. Preserve it for current frame/output safety. Renaming it into, aliasing it to, or using it as the adopted report-success epoch would break failed-publication semantics. Geometry must exclude it.
5. **Containing-source mutations.** Combined input reads capture both requesting-job and containing-source `output_epoch` using sequential report locks (`1687–1730`), then discard/retry stale work. This is useful when one job's admitted input is another job's replaceable output. A report-only save on that containing job also advances its output fence. Source descriptor equality must use actual selected-source facts; do not turn that unrelated report-only epoch into a permanent source/draft invalidation rule. An in-flight exact request may conservatively conflict on an overlapping mutation fence. A new render path/output epoch on the requesting job alone does not redefine its scan input.
6. **Output publication/read owner.** Combined `_send_open_file` uses one opened file's metadata/body, ETag and Range; request streaming holds all related lifetimes through close. `_RenderDelivery` owns output/report pair restoration and explicit recovery state. Neither supplies exact input stream/timing admission. After a delivery reports terminal success, common report publication notification must run without VAULT nesting; an early `publish_success` inside `commit` is insufficient because descriptor retirement can still fail and trigger restoration.

## Adopted sample/save representation to preserve

Endpoint/decoder policy spellings remain provisional in research (`GET .../edit_sample`, `cfr-index-v1`); the following adopted **structure and equality semantics** are fixed. A sample retains `source_ref,timeline_eq,policy,index,requested_s,canonical_s,observed_s,width,height,stream,origin,offset`, successfully encoded image and active raw rows including disabled rows. Resolve exactly once `i=min(floor(t*fps),N-1)` for finite nonboolean `0<=t<=N/fps`, canonical time `i/fps`, offset `cum[i]`, existing renderer visibility tolerance. No adjacent fallback, rounded stored spans, fabricated PTS, full-video hash or permanent sample ID.

```text
row_context_eq = digest(raw row excluding only
                        enabled,cbox,t_start,t_end,last_seen)
base = {cbox:[x1,y1,x2,y2], span:[t_start,t_end,effective_last_seen]}
effective_last_seen = row.get("last_seen", row["t_start"])
geometry_preconditions[raw_index] = {
  version:1,source_ref,timeline_eq,policy,index,width,height,offset,
  row_context_eq,base
}
```

All current/unknown context fields participate, including `poly,aoff`, category/group/manual creation. Same-index distinguishable reorder/replacement conflicts; indistinguishable duplicate semantic equality is adopted. Never search/rebind or introduce permanent IDs. `timeline_eq` incrementally hashes parsed fps/N/full ordered cum and selected stream/dimensions/orientation/source relation under its recipe, excluding output/audio/enabled/unrelated rows. Preserve opaque accepted JSON values; consumed geometry/timeline values require finite nonboolean checks. No extra full-report read, timeline copy/stringification or retained parsed report cache is justified.

| Submitted strict target | Allowed current tuple |
|---|---|
| Box only | `(B0,S0)` or already-equal `(B1,S0)` |
| Span only | `(B0,S0)` or already-equal `(B0,S1)` |
| Box + span | Whole `(B0,S0)` or whole already-equal `(B1,S1)`; mixed tuples conflict |

`S1.last_seen=clamp(S0.last_seen,new_start,new_end)` derives from submitted immutable baseline. Source/timeline/sample/context must match in every branch, including already-equal replay. Preserve raw absent `last_seen` for box-only edits. Return committed complete baselines/context in `geometry_rows` for submitted strict rows only; one conflict rejects the combined geometry/manual/choice/audio publication.

Strict identified manual replay computes immutable creation from submitted captured offset/box/times, compares existing valid `manual_creation` first and bypasses current source freshness only for that identical already-published addition. Genuinely new strict work leaves the lock without publication to prepare source, then reenters, reloads latest raw doc and reclassifies replay before validating. Current legacy creation instead uses latest cum and retains its existing replay semantics. Do not globally add source admission to choice/audio-only requests or acknowledge a new strict edit merely because a different addition replayed.

Later ACK adaptation retains one uncertain submitted snapshot until explicit retry confirms it; newer different/different-kind draft values survive. Only owned baselines advance to returned committed complete geometry. Scrub/reopen/sample fetch cannot silently rebase pending geometry. Strict seeds use the adopted capture-free `StrictSeed={pixels,source_selection,index,canonical_s,observed_s,fps,width,height,policy}`. Web verification capture closes before models; existing person/generic captures prime through the indexed helper but initializers always use supplied verified pixels. Legacy nearby seeding remains untouched when no strict seed is supplied.

## Concrete root rulings and acceptance ambiguities

These are bounded decisions; no new API name, policy, production tolerance or stronger support promise is adopted by this report.

- **Report-success notification and names:** approve distinct committed-report versus attempted-output-mutation state. In combined render, call report success notification after `delivery.commit` returns successfully, with report-lock/lifetime still owned; do not notify only in early `publish_success`, and do not change existing `output_epoch` semantics. Specify conservative in-flight exact conflict versus persistent source-ref invalidation when a containing job's output fence moves but its selected file stamp remains unchanged. This is a later integration requirement, not reason to add render delivery to standalone.
- **Canonical context equality:** select the minimal incremental encoding proposal below; keep it local to current context/timeline evidence and leave global report serializer and `_same_json_value` unchanged. No adopted rule requires opaque finite int/float or signed-zero collapse. Opaque nonfinite support is mandatory. Consumed coordinate/timeline finite checks remain fixed.
- **Endpoint/private symbols and shape limits:** freeze final route/helper names and exact supported field limits/error spellings against research's adopted `row_context_eq/base/geometry_rows` structure. Earlier example `row_eq` must not reappear as the save contract. No collision with these planned identifiers was found in either web source. Helper/source adapter names in research are illustrative.
- **Exact decoder/source policy:** choose named zero-origin FFmpeg/OpenCV metadata/sample admission and later measured observed-time bound strictly below half-frame. The old study's 1µs display tolerance is not production policy. `probe_vfr` returns a benign-looking result on missing/failing probe; it cannot be used as successful exact metadata admission. Native-CFR and retained normalized-CFR old dict compatibility must be demonstrated without inventing report fields. Agreeing rates/flags/cache mtime/count do not prove arbitrary whole-file CFR. Any stronger promise needs a root ruling, not an unconditional scan/hash or silent old-report rejection.
- **Overlapping report publication during sample response:** contract allows one bounded consumed-projection revalidation or a simpler 409/retry when a report publication overlaps decode/encode. Root may pick the smaller 409 path for backend. That choice must never become a whole-report epoch precondition on subsequent strict saves.
- **Explicit adoption recovery:** choose the existing exact request/reopen boundary and a fixed bounded retry shape for an unavailable current pair, with single current pending/adoption state and operation/report fence. No periodic job or recovery endpoint is authorized. Resolve duplicate simultaneous recovery attempts through the same descriptor owner. Final error must reflect current failure and suppress stale pregen.

No context is missing for the source-readiness deliverable. Implementation must resolve these decisions or report a concrete support contradiction to root; it must not silently resurrect superseded alternatives.

### Canonical-context options for root ruling

The final adoption states: “Keep canonical row-context equality compatible with opaque additive JSON values already accepted by the existing report reader/writer; finite/nonboolean requirements apply to consumed geometry/timeline fields, not a new rejection policy for unrelated metadata.” The earlier adopted row-context section requires canonical numeric/JSON equality consistent between response and save. It does not select type/zero normalization for opaque numbers.

Actual combined `_same_json_value` (`web:2005–2012`) first rejects differing `type`, accepts floats only when both are finite and equal, and distinguishes zero signs with `math.copysign`. It recursively compares lists and dicts; dict key order is irrelevant. Nonfinite values conservatively require publication even against themselves. That supports no-op elision and encoder-visible distinctions; replacing this function would change an unrelated reviewed policy.

|---|---|---|---|
| **Preferred proposal following root review; awaiting explicit selection** | Preserve `1` versus `1.0`, integer0 versus float0.0, and float `-0.0` versus `0.0`, as current encoder-visible forms do. | Incremental canonical encoder hashing with deterministic key order and escaping, using stable Python JSON extension spellings `NaN`, `Infinity`, `-Infinity`. For preferred proposal, use a private excluded-fields projection over the already parsed row, canonical key ordering/escaping and incremental encoder output fed to the existing digest recipe. Do not encode/stringify the full timeline into an intermediate string, copy its whole tree or build a generic canonicalization service. A timeline digest consumes only its separately validated finite projection. Recipe spellings/options must be shared by sample response and save; no Python built-in `hash` or browser `JSON.stringify` substitutes. Unknown opaque values survive raw report round trips as before; finite/nonboolean rejection applies only when such a value is actually consumed as coordinate/timing.
