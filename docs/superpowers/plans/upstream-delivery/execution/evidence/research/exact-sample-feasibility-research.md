## Supported decoder contract and explicit limits

The proposed first supported contract is the declared CFR scan timeline used by the existing report, with one selected video stream, known source-to-report relation, expected dimensions/orientation, and a tested OpenCV FFmpeg backend exposing usable post-read timestamps. Native CFR and the actual normalized CFR clip passed here. This is a practical supported-source contract backed by independent pixel tests; it is not per-request proof against an arbitrary decoder returning mutually consistent false metadata.

The upstream [OpenCV4.14 FFmpeg implementation](https://github.com/opencv/opencv/blob/0654a42e19215ef25b1d367d822f3c630447e7c7/modules/videoio/src/cap_ffmpeg_impl.hpp#L2302) explains the timestamp rounding and FPS-dependent integer seek; post-read time has backend normalization and PTS-property units differ from stream ticks. The bounded primary-source retrieval and complete interpretation are in [evidence README](exact-sample-feasibility-evidence/README.md). Those sources explain the tested backend, not a universal codec promise or binary reproducibility claim.

Minimal checks before exact success: finite valid request/FPS; nonempty coherent report timeline; current admitted source/report generation; supported stream/backend/timeline relation; successful nonempty image of expected dimensions; finite decoded time agreeing with the selected CFR sample under the documented backend time-origin/time-base policy; successful image encoding; and current ownership/generation again before detached publication. Zero time is valid for the first sample, not automatically missing metadata. A backend reporting zero for every frame, unsupported PTS behavior, failed/mismatched read, source change or inconsistent report/decoder facts must produce an unavailable/conflict response, never an earlier exact image. Position counters and `cap.set` alone cannot satisfy these checks.

Use the scan's established timeline length and relation to bound editable indices, with capture count metadata as a consistency hint. Do not blindly certify `N=duration*fps`, silently truncate the report to a smaller advertised count, or treat `avg_frame_rate==r_frame_rate` as proof that arbitrary media is CFR. Known ordinary/managed CFR sources can use the supported path; unsupported/native VFR (`--no-vfr-fix`/`vfr=ignore`), missing or incoherent timing, multi-stream ambiguity, rotations/transforms and unfamiliar backends need explicit unavailable geometry until a corresponding contract is validated. Metadata checks are useful failure detection within the contract, not immunity to hostile metadata. This research does not require a new full-video scan to establish that immunity.

No stronger extraction was needed for the three retained cases, so **no alternative FFmpeg extraction algorithm was compared or proposed**. Integer seeking itself may decode from an earlier keyframe, potentially from the beginning on a single-keyframe file; this research neither measures nor removes that cold prefix work. The bounded sequential references above are a test oracle, not a production algorithm. No per-scrub full prefix scan, full-video hash or persistent frame/PTS index is required by this recommendation.

## One coherent exact-edit owner

1. **Resolve source/report/sample together.** Admit existing P06 file/source ownership before I/O. Reuse the current per-job report transaction and source generation boundary to obtain an immutable request-local descriptor: job incarnation, selected admitted source and observed file identity, report identity/timeline, dimensions, stream and integer index. Decode outside report lock, then revalidate before returning. Prefer one exact-edit endpoint returning encoded image plus geometry/sample metadata in one response; fetching pixels by a separate URL requires the same descriptor token and equality checks. Do not reread two independently selected sources/documents and call them one sample.

2. **Choose the endpoint explicitly.** For valid finite `0≤t≤report_duration`, resolve `i=min(floor(t*fps),N-1)` once. This maps the entire final frame interval, including exact duration, to the last sample. Reject invalid/out-of-domain requests; do not disguise arbitrary out-of-range input as fallback. UI may retain its existing tenth-second slider but the label must distinguish requested time from resolved sample time/index, including the final clamp. Offsets come from `cum[i]`. Geometry visibility is evaluated at the same resolved scan sample time that the renderer uses under the declared CFR relation, preserving stored interval endpoints and existing detection/render rules. Keep observed decoded time separate from requested time and canonical scan time; **do not fabricate stream PTS by multiplying slider time or index**. Original integer PTS/time-base fields are optional unless an adopted backend can actually supply them. Backend-observed presentation seconds plus verified source/index suffice for this narrow editor contract; any P17 schema remains provisional.

3. **Bind readiness to this same mounted selection.** On scrub, invalidate sample readiness and end in-progress geometry gestures immediately; retain ordinary saved/pending drafts. Capture existing job/view/editor ownership plus a monotonically changing request serial local to this editor mount. Accept metadata and image decode/load completion only if they still belong to the latest request and equal source/sample descriptor. Enable pointer hit tests, drag/corner/add gestures and track launch only after image, dimensions/transform, offsets and boxes are all ready for that sample. Check the gate in handlers, including completion of two-click adds and in-progress drags, rather than only changing CSS. Failure/source change/empty image keeps old pixels visibly unavailable for editing or clears them. Closing, playback and job switches invalidate callbacks; pause requests a fresh exact sample before editing. Existing job/view guards alone do not solve same-view response races. P16D still owns live-resize correctness.

4. **Reuse source generation rather than create another identity store.** A managed normalization/rescan/source adoption, changed opened-file stamp, changed report/timeline identity or expired job incarnation invalidates pending samples. Obtain file identity from an opened source where practical, compare before/after decode and at publication, and coordinate managed changes through the existing owners. OpenCV's pathname API does not itself guarantee that a preliminary file descriptor and its decoder opened identical immutable bytes; account for this race within the declared managed/observed-file contract. Size/mtime alone is too weak; established descriptor identity can include device/inode/size/high-resolution mtime/ctime and managed epochs, subject to platform limits. A short-lived opaque source/sample token represents that live ownership relationship, **not a durable content digest**. Reuse a matching descriptor; discovery cannot endlessly mint new generations. Arbitrary external in-place writes preserving every observed attribute remain outside the fast contract. No whole-video hashing on every scrub is implied. The existing scan digest belongs to durable source-byte identity and later stored/reopen checks, not a second ephemeral generation scheme.

5. **Carry sample preconditions into saves and seeds.** Geometry deltas capture their own source generation, report/raw-row identity and resolved sample at creation; a later scrub does not retroactively relabel them. Under the current save lock/latest-raw-document transaction, validate these preconditions before subtracting `cum[i]`, applying row overrides/manual creation, and atomic publication. Use resolved integer/index-specific offsets rather than recomputing from a stale requested `t_ref`. Keep existing manual replay IDs, raw unknown fields, output/audio choices and P07a value-equality ACK snapshots. A source/row mismatch conflicts and retains drafts. Avoid a global blanket report revision requirement that breaks unrelated choice saves or idempotent replay: first recognize an already-published identical manual creation under its existing replay rules; otherwise validate the geometry's relevant source/timeline/row preconditions. Choice/audio-only edits need no decoded sample. Durable frame-bound P17 data uses the established scan identity where available and its later render/reopen mapping contract; do not persist a volatile token as byte identity.

6. **Tracking requires the actual initial sample at its initializer.** Validate source/sample at launch before model work; pin the admitted source through execution and existing publication checks. Supply the smallest optional source/frame-bound seed input (or strict adapter) to the existing tracker entry: admitted source generation, resolved integer/sample and verified pixels. When supplied by the exact editor, every initial person/Vit/NCC branch must initialize against those same inspected pixels; do not silently move the drawn screen coordinates to a rounded or nearby initial frame. A fallback to another tracker can consume that same sample; inability to initialize it must fail explicitly. Preserve legacy callers and their existing nearby-initialization policy when the optional seed input is absent. Keep tracking algorithms, thresholds, defaults and propagation/loss behavior after initialization unchanged. Later intentional tracking movement is separate from initial inspected-sample identity. Until the adapter is integrated, block this exact-editor Track action. No model download/inference is needed for later tests that spy on which pixels enter each initializer. O02 reliability/keyframe/loss-policy changes and P10C cancellation remain outside this contract.

7. **Preserve intentional tolerance.** Compare still uses original/output-aware timestamp walk-back. Thumbnails and sighting previews retain their own representative selection/crop rules. Expose actual/fallback information where a time is displayed, without treating representative cache index as provenance or passing those responses into exact geometry. Source/output selection must be explicit for exact requests; ordinary box geometry targets the admitted scan input, not a rendered output.

Normalization assumptions are narrow. The normalized scan copy is the editor's source, so normalized indices/duplicate frames are retained as separate timeline samples. A normalized index is not the corresponding original VFR ordinal. HDR scanning uses tone-mapped SDR pixels; the actual normalizer can use original or CFR HDR render sources. `_scan_copy_matches` at6496 allows count tolerance2 and returns true on unknown counts, so it does **not** establish a certified per-frame SDR-to-HDR relation. Identical count alone would not establish that relation either. Source-bound P17 geometry may apply to the verified scan/SDR path; unsupported original/HDR mapping must preserve full-plate fallback and leave HDR acceptance open. No new tone-map, detection or render algorithm is proposed.

## Smallest implementation split and remaining gates

**P10A backend slice:** a private request-local sample/selection helper beside the current reader; accept integer index, retain observed decoded presentation time, perform the above finite/read/source checks, resolve boxes from the same immutable request snapshot, and expose one exact-edit response using existing P06 owners. No worker, queue, general media framework or new persistent store. Add geometry save preconditions at the existing transaction boundary; keep API/field spellings provisional until implementation.

**P10A editor slice:** consume that response atomically, implement latest-request/readiness/input guards and resolved sample labels, and carry each geometry draft's sample precondition through existing save/ACK ownership. These may be two dependent reviewable changes, but an enabled editing path requires both.

**Dependent P10A-S seed-contract sub-PR:** add the optional verified seed/strict adapter described above across the existing person/Vit/NCC initializers and actual Track route; legacy callers without that input keep their defaults. The editor Track action remains gated until this lands. This dependency is justified because merely sending canonical time into the tolerant existing helper can still select another initial frame. It contains no O02 tracking/loss-policy/keyframe feature or P10C cancellation work. P10B and P17 remain separate deliveries.

Acceptance still required, **not run here**: actual integrated Flask image/boxes/save flow and three ordinary browser cases; same-view reordered response and image decode/load schedules; pointer/add/drag/track gating during scrub/playback/error/source replacement/job switch; per-draft preconditions with unrelated choices, replay/lost ACK and source/report conflict; actual initializer pixels for every supported tracker entry without invoking models; stale-source publication/discard with managed normalization and external observed replacement; lifecycle lock order/release on native exceptions and failed encoding; supported platform/OpenCV versions and time-origin/fractional-FPS/codec/stream/orientation contracts; nonnormalized VFR refusal; P16 transforms and P17 HDR mapping. Required delivery tests/build belong to implementation, not this read-only research.

Long-GOP/4K/high-bitrate cost, native hangs, cancellation kill/reap, concurrent saves during blocked decoding and worker limits remain P10B gates. There was no runtime/latency benchmark or universal decoder/metadata guarantee. No source replacement, corrupt/truncated media, multiple streams, fractional FPS, negative/nonzero timeline origin, HDR or Windows decode was exercised. Do not promote these tiny H.264/Linux observations into those claims.

## Delivery-order amendment

2026-11-17. Sequencing clarification only; no code changed and no decoder, runtime or verification probe was rerun. This amendment supersedes any implication above that the ordinary editor should switch to the exact path while its existing Track button awaits a later seed adapter.

Prefer this dependency order:

1. **Backend exact-sample contract and optional geometry preconditions.** Add the supported indexed sample owner and optional source/sample/row preconditions at the existing save boundary. Keep the current ordinary UI and legacy callers usable. Requests without the new optional preconditions retain their current behavior; introducing the backend does not silently tighten unrelated legacy requests.
2. **Optional strict seed adapter.** Add the source/frame-bound initial seed input for the existing tracking entry and each supported initializer. When supplied, it must use the inspected sample or fail explicitly; it cannot silently initialize at a rounded or nearby frame. Calls without that input retain their existing behavior. Tracking algorithms after initialization, O02 policy and P10C cancellation remain separate.
3. **Switch the ordinary editor and its Track action together.** Consume the complete exact image/geometry sample, enforce fallback-free readiness and input gates, carry geometry preconditions, and submit the strict bound seed from the same mounted selection. Land this UI change only after both backend contracts exist. Do not deliver an enabled ordinary exact editor with its existing Track button disabled pending a later PR. Actual unavailable or failed exact samples still block geometry and Track input consistently in the final path.

These may be three small dependent PRs, or backend plus seed support followed by one UI PR, depending on the actual diff. Each intermediate PR preserves usable legacy UI/callers. Public field, token and PTS spellings remain provisional until implementation; this ordering introduces no additional identity store or capability framework.
