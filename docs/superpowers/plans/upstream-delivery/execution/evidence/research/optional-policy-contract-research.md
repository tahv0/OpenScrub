## Recommended minimum additive contract (source-only)

Use a small evaluator, not a general state machine: existing retained candidate + explicit output intent + observation/geometry evidence + policy/cutoff → effective output and suggestion/gap status. Scope automatic policy to plate evidence for O01. Keep other categories and existing exclusions unchanged.

**Settings.** Add only per-job `uncertain_policy` (`manual_review` or `blur_candidates`; absent means upstream/off) and `plate_auto_cutoff`. Retain `plate_threshold` as the scan's candidate floor. In an optional request require finite `0.05 <= plate_threshold <= plate_auto_cutoff <= 0.95`, rejecting invalid pairs rather than independently clamping them into a different request. Keep the existing absent/off default normalization path untouched. The pair 0.35/0.80 is illustrative and must not become an approved or silently shipped measured default. Initial optional cutoff and continuity window require later fixed-clip measurement. Until selected, an experiment must supply its cutoff explicitly.

Job `options.json` is the initial scan/retry input (C web L498–517, L673–691, L4870–4888); `_settings_dict` captures primitive args into report provenance (C engine L6118–6128). Use the report's optional settings as canonical **after scan**, including reopen/from-report rendering. Do not require an unprotected two-file options/report transaction to switch policy. A postscan floor change requests a rescan; lowered floor evidence is missing, and O01 has no safe cross-rescan identity/choice transfer. Changing cutoff within the retained floor can recompute automatic output.

**Output intent.** Add one optional row scalar `output_choice: "blur" | "keep"`; missing means no explicit choice **only within a new, provenance-capable optional report**. Keep `enabled` as the materialized effective output consumed by current render/review boundaries. Avoid a separate explicit boolean plus independently editable choice value. An unresolved suggestion is `output_choice` absent and `enabled=false`, not an explicit Keep. Automatic output is `output_choice` absent with evaluator-derived enabled. Expose human/automatic/suggestion/gap display labels as derived values; do not add histories, a second decision registry or per-frame copies of the report.

**Evidence.** On the existing per-sample rows in a new optional scan, add a compact `policy_evidence` object containing sample origin, original source-frame index for a genuine observation, and geometry validity/reason. Origins need to distinguish direct plate detection, visually supported continuation, manual seed, interpolation, unconditional grace and held/weak coverage. Synthetic entries have no independent detector observation. The initial source frame must be recorded before `t_start` is widened by smoothing; job source identity must match the report's scan source, not merely a filename. Existing `confidence` is adequate only for the direct detector origin and only with an explicitly specified stored-score/rounding rule. The smallest replayable O01 rule uses the existing three-decimal stored plate confidence consistently, including equality at cutoff; if full-precision scores are desired, retaining that value before decoder/scan rounding is a concrete additional prerequisite. Do not infer full precision later.

A single report-level optional evidence-format marker is needed to distinguish a new complete provenance contract from legacy partially missing fields. This is a serialization capability marker, not a decision revision/history. `policy_evidence` can remain optional-only raw fields merged at serialization; it must not add default report fields or alter the default `Detection`/render path merely for convenience. Existing per-sample rows carry the evidence; no second observation array or registry is needed. A missing/invalid evidence field in a marked optional report must conservatively yield no new automatic support and a gap/unknown status, never invent a valid observation.

**Truth table.** Human output intent takes precedence over automatic policy; geometry validity remains an independent prerequisite for applying a mask. A high score or explicit Blur does not invent a missing location. Explicit intent is retained during a gap for O02 correction.

The binding proposal is two associated valid observations for optional automatic activation; human selection may seed immediately. Recommended bounded experimental interpretation: distinct source frames; both genuine retained direct detector observations; each score at/above cutoff for `manual_review`, each at/above candidate floor for `blur_candidates`; no duplicate timestamp, interpolated box, OCR string match or tracker-held box counts. Activate at the second supporting observation without retroactive automatic onset extension; earlier unresolved evidence remains a suggestion. These exact score eligibility, time-window and activation-onset choices are **recommendations requiring supervisor confirmation and later clip measurement**, not accepted measured behavior. The modes then differ by score eligibility, while both retain the proposed two-observation safety boundary. If an immediate single-hit `blur_candidates` tradeoff is desired, it must be an explicit revised brief decision, not inferred from its name.

Geometry validity needs actual supplied geometry evidence, not just a finite confidence. Validate finite nondegenerate coordinates in the matching frame/source system; structural validity alone does not prove object coverage. In a minimal O01 experiment, a direct detection supports its decoded frame; skipped frames, synthetic onset/exit and unvalidated interpolation remain gaps. Wider supported intervals require an accepted continuation contract from O02. Do not silently apply the upstream grace/hold span as evidence of validity. This conservative boundary may produce many gaps at stride >1 and delay short true targets; those are required measured tradeoffs, not claims of improved accuracy.

### Conservative legacy compatibility boundary

A legacy row's enabled flag tells us saved effective output. `zone_dropped` may explain some original exclusions, `manual_id` identifies creation replay, and track/person identify grouping. None establishes whether every current enabled value came from a human click, a default, an exclusion or an automatic process. An enabled true row may be untouched or explicitly Blur; false may be explicit Keep or zone-derived. Absence of `output_choice` is not historical proof of either intent.

Recommendation: legacy reports open, save, render and export with their saved enabled values unchanged. Display origin as unknown/saved legacy output if necessary, never as “human confirmed” or “unhandled suggestion.” New explicit clicks can acquire `output_choice`, but remaining legacy rows cannot be automatically recomputed. A legacy report without complete observation provenance is outside in-place optional policy activation; keep its saved output rather than treating absence as opt-in. This is a feature capability boundary, **not** a review/export gate: ordinary export remains available, with no required approval queue or mandatory rescan. A fresh optional scan creates a separate evidence-capable result; O01 cannot promise to transfer legacy choices across rescanning, because stable identity/reconciliation is not established. An in-place conversion would require a separately approved mapping preserving unknown legacy output and demonstrably complete source-bound evidence; copying enabled into “human choice” is not that mapping.

Turning optional modes off on a new evidence-capable report retains its explicit choices and provenance; untouched eligible plate rows return to their known upstream scan inclusion, while unrelated/excluded output is preserved. Switching it on again recomputes automatic rows from retained original evidence. Do not apply this restoration inference to legacy rows or rows created by unknown writers. Reopen uses saved report settings and intent; re-render must not reset them from stale initial job options.

## Placement and the O02 handoff

Collect original sample tags at admitted plate creation, retain association membership immediately after existing `assign_dense_tracks`, and evaluate optional activation against that original evidence. Smoothing can continue in the existing finalization position, but its synthetic spans are classified separately; it supplies no independent activation evidence. After finalization/manual append, compute effective output for the render subset and materialize report enabled state from the same decision function. Reuse the same function during policy changes/reopen/from-report rendering so first render and later render agree. Off/absent returns directly to the untouched upstream path.

Exact evaluator inputs are: selected policy; retained scan floor and requested cutoff; explicit output choice; source identity; each original sample's frame/time, geometry and origin; existing association ID; and supplied geometry-support intervals/status. O01 may check the existing association's category/time/space constraints but cannot solve crossing identities, correction/re-entry or lost continuation by inventing links. Evidence-less synthetic boxes and matching text never increase the valid-observation count.

O02 owns source/frame correctness, selected-target identity, immediate seed admission, continuation reliability, correction keyframes, loss intervals and retracking. Its required interface contribution to O01 is source-bound observations/geometry status attached to existing target/track samples plus the retained output intent. O01 consumes those facts; it does not decide a tracker algorithm or convert seed confirmation into permanent geometry validity. Current zero-score frozen/weak samples are unequivocal unsupported locations; positive default tracker samples still need an accepted O02 reliability contract before automatic optional continuation. P10/P16 exact-frame work is a prerequisite only if O02 relies on it; this investigation did not inspect or accept those tasks.

### Binding mode and compatibility decisions

The supervisor has resolved the optional mode distinction:

- `manual_review` uses the proposed **two independent cutoff-eligible observations** before automatic activation. Independent means distinct genuine associated source observations; an interpolated/grace/held box or duplicate same-frame hit does not add support.
- `blur_candidates` permits **one retained floor-eligible hit** when its location is supported. Short extra masks/flashes are a deliberate tradeoff of this explicitly requested mode. The earlier recommendation that both modes require two observations is **superseded**; a single supported retained hit is no longer a suggestion merely because a second hit is absent in `blur_candidates`.
- Both modes retain geometry-gap handling. A score, a retained hit, or explicit Blur intent does not establish an unsupported location. Human choices retain precedence over automatic policy. Exact cutoff/window parameters and observed quality remain **unmeasured**. This decision supplies no measured parameter default or accuracy acceptance.

Optional `output_choice`, sample evidence and the report capability marker are written **only for a provenance-capable optional report**, including when that report's mode is subsequently switched off. Ordinary absent/off reports and legacy reports retain their existing raw schema and authoritative saved `enabled` output, with **no automatic conversion**. A legacy explicit click uses the existing enabled write; it need not and must not acquire a new optional `output_choice` field just to preserve that output. Saved enabled output is authoritative for legacy rendering without establishing historical human provenance for every row. An optional settings request cannot silently enroll an ordinary report in the new schema. Ordinary/legacy open, save, re-render and export remain available; no review/export gate or compulsory rescan is introduced.

This narrows the original report's statements that all indexed/manual/track writers should add intent and that new legacy clicks could acquire `output_choice`: those additions now apply **only inside the optional report capability boundary**. The choice writer must first know that boundary. Previously optional reports keep their capability/evidence/intent when off, so a later policy switch can preserve human choices. The old ordinary report path continues its current enabled behavior.

The current `Detection` is an ordinary `@dataclass` without slots (C L733–751), so an optional internal instance attribute is structurally feasible without changing its declared dataclass fields. **Do not add optional fields with `None` defaults to the shared dataclass merely to transport them:** fresh `write_report` uses `asdict(d)` at C L6394–6397, so declared fields would appear in ordinary reports too. Conversely, dynamic attributes are not dataclass fields: the current `asdict` writer will omit them. A capability-gated encoding step at the existing fresh-report row writer is therefore a concrete prerequisite for this owner choice, not functionality that already exists.

The directly relevant interfaces are:

1. Dense `merge_detections` returns the same dense objects (C L2985–3000), and `assign_dense_tracks` mutates their track IDs in place (C L1361–1389). Thus original plate metadata can remain attached through these stages. Capture original source frame/time before smoothing mutates spans.
2. `smooth_dense_tracks._mk` creates **new** `Detection` instances from a reference and copies its confidence (C L1433–1442). It does not transfer any optional metadata. Those new objects must receive their own synthetic-origin/gap classification at creation; copying the reference's detector-observation identity would be wrong. This is a required creation-site change inside the optional capability branch, not an inferred guarantee of automatic propagation.
3. `apply_coverage` returns original plate objects, and shallow-copies dense person/manual samples when changing coverage (C L3811–3836). Any mutable internal optional payload on such a shallow copy would be shared. Evaluate/filter geometry validity before coverage and treat attached evidence as immutable, or explicitly detach it when a copy needs independent modification. This check establishes the aliasing risk; it does not select an implementation of copy ownership.
4. Fresh `write_report` currently forces enabled true/false by its existing inclusion lists (C L6394–6397). Its optional-capability branch must encode the attached evidence/intent and materialized effective output while retaining suggestions in the full report. Its ordinary branch must remain byte-equivalent under the same inputs. From-report `write_report` already preserves raw source rows (C L6371–6389), but `_decode_report` reconstructs only declared fields (C L6424–6446): a capability-gated decoder/hydration step is needed before optional recomputation on reopen. Raw-field preservation alone does not hydrate the internal owner.
5. `_settings_dict` includes primitive values from **all** `vars(args)` entries, including `None` (C L6118–6127). Adding optional parser defaults can therefore leak new keys into ordinary provenance even if no optional sample field is serialized. The ordinary settings writer must omit new optional keys when the report lacks capability; a previously optional report that is now off retains its saved optional settings/evidence through its capability. This is a second concrete prerequisite for absent/off report-byte equivalence.

These findings establish a feasible narrow owner and the exact serialization/creation/copy boundaries that need an implementer contract. They do **not** establish implemented propagation, byte equivalence or reopening behavior. Internal payload name/type, marking of synthetic/manual creation sites, optional encode/hydrate signatures, immutable payload enforcement and report/settings selection at each caller remain implementation mechanics to specify and test. No metadata is to be inferred from final representative confidence, span length or group membership. O02 still owns exact seed/identity/continuation/loss handling; this amendment does not design it.
