The smallest separate fix contract is:

1. At the shared create-route boundary, decode the supplied `options` field once, catch malformed JSON/type errors, and require a JSON object. Return a clear JSON **400** such as the donor's generic message before `new_job`, input copying, options persistence, registration or enqueue.
2. Preserve omitted options as `{}`, explicit `{}`, ordinary supported objects and the existing unknown-key policy. Explicit empty text and whitespace currently fail parsing and should become a clear 400; this is not removal of an accepted default. Explicit `null` and every other non-object must be rejected even when falsey. Do not use `json.loads(...) or {}`.
3. Apply the same contract to multipart uploads and ordinary server-path intake. Parsing may still cause ordinary framework form buffering/spooling; the contract concerns durable job/queue side effects.
4. Keep this fix independent of report saves, polling, retention, job lifetime and donor learned-model/narrow-specific features. The interface interaction with the current work is confined to new-job admission: accepted requests continue through the existing `new_job`/`enqueue` interfaces, rejected options never reach them.
