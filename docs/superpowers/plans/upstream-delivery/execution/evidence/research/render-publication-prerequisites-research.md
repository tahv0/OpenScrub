## Concrete delivery/rollback design proposal

These private names and algorithm details are proposed for root adoption, not existing implementation.

### Paths, names and owned lifetime

Use exclusively generated 32-lowercase-hex task tokens. The proposed primary video stage is `.render-<token>.tmp<original-container-suffix>` beside the final video. Preserve `.mp4/.mov/.mkv` and any other existing supported container suffix, including case-independent encoder checks. The fallback's owned intermediate is that stage plus `.noaudio.mp4`. Terminal `.tmp` alone must not replace a meaningful suffix and change FFmpeg format inference, audio container choice or hvc1 tags. For a no-extension destination, preserve its existing actual backend behavior: fallback can still replace its intermediate; do not invent universal MP4 inference for FFmpeg. Any explicit muxer adaptation needs an owning compatibility case.

Report stage remains `.report-*.tmp` beside its own final. Proposed recovery names are `.render-recovery-<token>.video`, `.render-recovery-<token>.report`, and `.render-recovery-<token>.json`; these never end in `.tmp`. Distinct destination directories get sibling stages/backups at each final, not cross-device rename. Descriptor lives beside the report when present, otherwise beside the video. Web defaults put both within the owned job tree.

Vault's shared predicate preserves its existing terminal `.tmp` rule and additionally matches only the exact generated video-stage grammar, including the exact fallback intermediate. Escape/validate the token and suffix grammar; a broad `.render-*` or hidden-file rule would delete recovery/user files. Recovery artifacts are encrypted/decrypted and counted as sensitive ordinary files, including their descriptor. Cleanup must not depend on encryption discarding them.

Reserve descriptors with restrictive exclusive creation and close before encoder/replace. R must finish/reap/close each actual media reader/writer/child/pipe before the delivery can delete its stage or publish final paths. Keep the admitted operation and selected-input/related-source lease through render, hash/report, backup, commit/rollback and cleanup. Leave report locks before lease release. Successful direct render still returns the legacy result shape; only final paths appear in successful results/report provenance/`job.output`.

### Effective destination and previous destination snapshot

Reject report and video pointing at the **same effective destination entry** before resource acquisition. Compute the key from exactly the path normalization used by that final publisher: resolve the containing directory and retain the final basename/leaf entry (and platform case rules); do not blindly resolve the final symlink or compare `samefile`. Keep the publisher's path semantics consistent with that key. A symlinked parent can alias a directory entry. Distinct hardlink names are independently replaceable entries; distinct final symlink entries can also be replaced independently. Test their actual resulting entries. Preserve current path-confinement policy.

Source==final-video is permitted where already supported, especially the fallback. The source is read before final publication and retained through the existing source lease; no self-reader counter can deadlock commit. Hash/report input provenance must be captured before successful same-path replacement. A report overwriting source is a separate configuration/policy question; preserve existing policy in this task rather than adding an unrequested source-path ban. Do not claim universal in-place FFmpeg/HDR/audio/platform support without real tests.

Before commit, snapshot both finals, including explicit absence, with entry identity (`lstat` device/inode/type/size/mtime/ctime and symlink target where applicable) and the relevant parent/path identity. Prepare rollback artifacts outside all shared locks while the operation's active mutation gate excludes cooperating writers. A simple initial implementation may copy regular previous files into exclusive 0600 sibling backups (one backup per operation, **not per read request**), sync/close them, and recheck old identity around the copy; this avoids the identity/ctime mutation caused by making a hardlink. Preserve a prior symlink as its entry/link target if supporting that entry type, not merely a copied referent. Reject unsupported backup preparation safely before final mutation. Do not move old finals away to prepare backups. No full metadata/inode preservation or defense against an external concurrent writer is implied by byte/existence preservation.

After preparation, the web hook under report lock rechecks live owner/Event, recovery gate, both final entry identities including absence, and directory/path target identity. If anything changed, leave the lock and discard/reprepare outside it or fail explicitly; never publish against stale backups or copy inside the lock. Default CLI/GUI has the same precommit identity check but no new cross-process coordination. External/direct-CLI writers into live web directories remain outside the managed contract.

### Preprepared recovery descriptor

Prepare the small descriptor **before any final mutation, outside locks**, with a format version, token, final role paths, previous-presence flags, backup role paths and selected-source hint sufficient to identify the affected task. Use the existing serializer/stage helper for descriptor JSON too if convenient; it is not a second report document. Store no operation Event, key, handle or raw exception traceback. Public errors reveal only recovery-required and bounded safe diagnostics, not arbitrary local paths.

The preprepared descriptor is enough to identify original/backup roles if the filesystem refuses further writes after failed rollback. An optional later update can record exact attempted/failed steps, but retention must not depend on writing it then. Keep necessary stage/new bytes as well as every backup still needed after failed rollback; error carries primary + bounded rollback diagnostics in memory.

A proposed success order avoids a descriptor silently outliving acknowledged success: after both replacements and terminal field assignments under the report lock, remove the descriptor as the last fallible authoritative commit action; only then mark the local outcome committed. If its unlink fails, roll back finals and terminal fields while backups still exist. After that point, remove unneeded backup/stage leftovers outside locks without turning committed success into a fictitious render error. If a rollback succeeds but descriptor cleanup still fails, expose conservative recovery/cleanup-required state; the descriptor's existence must never be ignored on restart. Backup/stage cleanup failure after committed success gets bounded cleanup diagnostics, with no false claim that final bytes rolled back. No promise for process death/MemoryError between arbitrary Python assignments.

Rehydration first recognizes a **strictly named** recovery descriptor in the job directory. It must surface a safe error/recovery-required job even if report JSON is absent/broken or `output.mp4` exists. Initialize normal `_JobFiles` state and retain uploaded-source/options hints through existing admission rules; never use descriptor paths as authorization to open arbitrary files or automatically restore them. A malformed matching descriptor is conservatively recovery-required, not silently ignored. Restart does not establish what crash point occurred or whether the pair is actually corrupt. This is discoverability/manual-recovery evidence, **not automatic crash repair**, a permanent archive or durable transaction journal.

### Commit, rollback and status boundary

For P render delivery, all media encoding, report construction, full input/output hashing, stage serialization/fsync and large backup copies occur outside report/JOBS/VAULT locks. Existing edit transactions retain their owning latest-read/apply/publication scope. Under the render delivery report lock, perform only short final mutation attempts and status work. Validate `_operation_valid(job, owner)` and the captured Event once at admission to this boundary, keeping P06 cancellation semantics: a cancel may signal while a commit owns the lock; a completed commit before cancellation acknowledgement is legitimate and cannot be relabelled cancelled. A cancellation acknowledged before commit invalidates the identity and must prevent every final mutation.

For new/default paths, commit staged video then staged report; video-only commits just video. Legacy callback is the explicit second-action exception above. Track attempted and successful final actions, and restore conservatively when a second action may already have changed the report before raising. For each original-presence combination (both, video only, report only, neither), restore original bytes/entry or absence for **both** finals. Preserve the original publication exception object after successful rollback; report ordinary error, retaining previous `job.output` and prior terminal field snapshot. Restore any partly assigned output/phase/progress/eta/error fields if their authoritative assignment raises ordinarily. Backups remain until those assignments and descriptor retirement finish.

If restoration replace or absence-restoring unlink fails, retain the descriptor and needed artifacts, raise `_DeliveryRecoveryError(primary, rollback_diagnostics)`, set explicit error/recovery state under that same boundary, and never advertise the pair as valid or return a clean cancellation. A recovery marker takes precedence over later generic cancel/error handlers even if cancellation invalidated the operation while I/O was finishing. Output/report/compare and render/edit/tracker admission must refuse this unresolved state; status remains readable, intentional delete follows existing lifetime rules, and vault may encrypt normally once leases close. Do not permanently pin failed jobs with a leaked lease.

`_run_job` records a local committed result and does not independently assign done after `run_pipeline` returns. Expected cleanup and nonauthoritative completion notifications cannot overwrite that result. This removes the existing `1093` gap between report-hook return and terminal state. No database or multi-process writer coordination is introduced.

## Epoch and response boundaries

### Every managed final mutation attempt invalidates before I/O

`_JobFiles.output_epoch` is a monotone Python integer. Under the same owning report lock, increment it **before every attempted relevant managed final video/report replace, rollback replace, or absence-restoring unlink**, including failed attempts which made no visible change. Never restore or reuse an earlier epoch after rollback: identical restored bytes/path still invalidate the overlap (ABA). Private stage/backup/descriptor cleanup is not final-generation publication and does not need an epoch bump.

Inventory and route all managed final writers: new pair/default web render hook; scan's legacy final report hook; save-edit and tracker report publication. A small web-local `_publish_job_report_locked` can use the shared `_staged_report` and bump immediately before its final replace; retain existing latest-read/apply transaction scope for edits. Do not leave a direct `atomic_report` call as a bypass merely because it is report-only: per-job epoch may conservatively invalidate another short frame read. P06 scan/edit serialization behavior remains its owner; P's staged-render construction outside locks does not justify moving latest-read/apply out of its transaction.

Deletion/vault cannot ordinarily overlap these readers because their existing FILES leases exclude those transitions. Rehydrate initializes fresh state, and deleting identity/closed checks reject old captures; do not invent epoch persistence or a global path registry for them. If implementation discovers another cooperating writer able to mutate a selected live output during an admitted read, add its short owning boundary and test it; report any uncoordinated writer as a limit, never hide the omission behind output-path equality.

### One short frame attempt, at most one complete retry

1. Retain existing request FILES ownership before any report lock. Use the admitted owning job/state for the selected managed output, including canonical source aliases. Under that report lock, check exact live identity/closed/recovery status and capture `(owner job/state, epoch, selected path/source identity, output-versus-fallback selection)`. Select `job.output` here; preserve `_job_video(job)` fallback without switching paths mid-attempt. If fallback follows another managed output, use that source owner's epoch, not the requesting job's epoch. Avoid nested report locks; admitted references permit the separate owner selection/revalidation steps.
2. Unlock. Construct/probe/seek/read the decoder, including existing timestamp/backoff behavior, and release every actual capture in finally. Copy/detach the result as needed and encode JPEG outside all report/JOBS/VAULT locks. Hold either detached bytes/frame or the stable-source error for validation. Constructor/open/decode errors also pass through validation; a transient overlap must not escape as an early 404.
3. Reacquire only the captured owner's report lock. Recheck job/state live identity, closed/recovery status, exact selection/source identity and epoch. A stable attempt returns its detached bytes or existing normal error. An invalidated attempt discards **both** pixels and transient error and retries the complete flow once. Two invalidated attempts return explicit HTTP409 `output changed during frame read; retry`. Recovery-required is its explicit refusal, not ordinary staleness.

Successful final revalidation is the response's linearization point. A later commit can coexist with transfer of detached older JPEG. This does not guarantee newest-at-transfer completion, consistency between two requests, physically immutable lazy decoder inodes, cancellation/deadlines for stuck native calls, or an immutable generation for long-running intake/inference/hash/audio readers. Those long-running readers keep their existing lifetimes only; no reader count, commit-pending gate, full-media request copy or generic source-use subsystem is selected.

### Descriptor, metadata, conditional and Range identity

For download/report and admitted source-output aliases through `job_video_stream`/`server_video`, select the final path and actually open the response generation while holding the correct short report lock. Derive Content-Length/Last-Modified/ETag/Range/conditional behavior from the **same descriptor generation**, then unlock before transfer. Retain that descriptor and the owning primary/related FILES lease through `OwnedIterable.close`, including normal exhaustion, early disconnect, 304, 416 and exceptional construction/iteration. Do not release a needed child source lease in `after_request` while a detached stream still reads it.

The configured installed Flask/Werkzeug behavior is a required real check: does `send_file(path)` open at response construction, and is X-Sendfile disabled? A lock around deferred path reopening is insufficient. If necessary, use a small explicit opened-file response helper preserving framework conditional/Range semantics with metadata from `fstat`; avoid building a generic HTTP stack or whole-file hash/buffer. A file object alone does not prove the framework computes correct Range headers. Preserve actual seek/body and If-Range/If-None-Match/If-Modified-Since behavior at the configured server boundary.

Already-open POSIX old streams may finish while a new generation replaces final names. Native Windows/file-system refusal may instead trigger ordinary publication/rollback error; do not claim concurrent successful replacement there from POSIX results. Independent video/report HTTP requests intentionally may straddle commit; no pair export snapshot is promised.
