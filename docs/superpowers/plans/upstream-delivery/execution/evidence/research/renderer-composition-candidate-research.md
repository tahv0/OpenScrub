## Sole metadata cleanup owner

`git grep _geometry_metadata` over **all** reviewed G objects finds exactly definition G3201 and two production callers G4033/G4211, with no external/test callers. Both callers map to the two R bodies above. Therefore the helper can become validation-only without orphaning another capture owner:

- Keep value reads, `_geometry_finite(values,3,stage,"video dimensions/count")`, integer conversion and positive width/height check exactly as reviewed. Preserve finite negative frame counts; do not add a nonnegative-count requirement or exception coercion.
- Remove only the helper's `except Exception: cap.release(); raise` ownership behavior (and its now-unnecessary outer try). Let the actual geometry `ValueError`, native get error or conversion error propagate unchanged into R's existing `except BaseException as error: primary=error; raise`.
- SDR: `cap` remains owned until R's single finalizer loop; a metadata failure causes one finalizer release attempt. HDR: metadata failure leaves `meta` assigned for that same finalizer. On healthy metadata validation retain R's **early** `meta.release(); meta=None` before decoder spawn, so finalizer does not release it again after success. No helper or public wrapper releases either capture.
- If the finalizer release fails while geometry failed, retain the geometry exception object/traceback and attach R's bounded release diagnostic; do not replace it with cleanup failure. If cleanup fails without a primary, retain R's existing cleanup-error policy. This proposal removes a new double-release source; it does not promise or redesign R's pre-existing retry behavior if the healthy HDR early `release()` itself raises before `meta=None`.

A `finally: cap.release()` inside the helper would still double-own cleanup. Suppressing release exceptions there would lose R diagnostics. Moving validation outside the body try would leak the newly acquired capture. The validation-only helper inside each existing owner is the bounded composition.
