# P02 ordinary output-choice baseline research

Status: complete, 2026-11-17. Research only; no product changes. Fourteen bounded emitted-application browser scenarios passed. The concrete defect is that the card's single `Blur` / `Keep` button both describes its representative row and reverses that row's value; mixed groups have no truthful group state. Category and marquee actions are already explicit setters.

Grouping is category-local. Zone-dropped rows are removed before grouping. Within each category, a nonnegative `person` wins over `track`; otherwise a nonnegative `track` groups rows, and ungrouped rows get their own card. Person IDs are existing grouping handles, not a new identity/classification decision. Members sort by start time. Highest-confidence member supplies representative ID/thumbnail (ties retain the first time-sorted member); displayed time spans first start through last sorted member's end. Person cards precede other cards; then chronological order. `TRKMEM` is keyed only by representative ID. Neither shared track across different people nor shared person across different categories fuses their cards.

Mixed groups are fully supported by existing report flags, but the current card display does not aggregate them. For synthetic rows `[0,1,11]`, values `[true,false,true]` show the high-confidence representative 1 as `Keep` and dim the whole card. Track `[4,5]` with `[true,false]` shows representative 4 as `Blur`. Clicking either does not invert members separately: it sets every current member to the inverse of the representative's value.

The protection/setup choices (allow names, always blur, cover turned heads, modes, skip review), audio controls, allow-list confirmation and scan policy are separate behaviors. P02 must preserve them. Type/output/status filters remain P15. Neither default `enabled=true` nor a displayed output state means a person has handled/reviewed the group. No handled state, identity label, classification, training evidence, persistent choice field or report migration belongs here.

## Small explicit-setter contract

1. Use two enabled native buttons per ordinary or dropped card: **Blur** calls `applyDet(i,true)` and **Keep visible** calls `applyDet(i,false)`. Repeated actions retain the requested value. Keep action separate from visible current state. Never infer the requested action from a label, CSS class, current representative value or current `aria-pressed` value.
2. Derive displayed state from every existing member's live `EN` value, using `TRKMEM[i] || [i]`. Uniform true: **Will be blurred**, Blur pressed true / Keep false. Uniform false: **Will stay visible**, Blur false / Keep true. Mixed: **Mixed — N will be blurred; M will stay visible**, both false. In mixed state avoid whole-card kept/dimmed styling. These are output states, not handled/review labels.
3. A card action affects exactly its existing category-local membership; a zone card affects only its row. Clarify grouped scope locally, e.g. **Applies to all 3 appearances in this face group**. Existing broad person wording should not promise cross-category/zone propagation. Category and selected bulk continue acting on the same complete memberships. No regrouping, added metadata, cross-category fan-out or hidden learning state.
4. When any member changes through an existing path, refresh each containing card's aggregate text, styling and pressed state. A small local membership lookup/iteration is sufficient; keep editor row-local removal scope unchanged. Preserve `beFilter`/`beDraw`, `BE.sel` clearing, geometry/timing drafts, original/enlarged previews, thumbnail retry and marquee behavior.
5. Give each pair `role="group"` with an accessible contextual name (category/group/appearance scope), visible state text and boolean `aria-pressed` on both buttons. Keep both actions keyboard reachable and enabled, including the already-current action: a deliberate same-value action can carry P07a intent. Provide a clear focus-visible outline. Update text/attributes in place so focus survives activation; do not rebuild the focused pair. Do not claim `aria-pressed="mixed"` means human review.
6. Rename category on/off wording to explicit output verbs; keep existing zone bulk setters and use a truthful neutral zone summary. Selected menu `Keep visible` / `Blur` stays explicit. No new global keyboard bindings, selection system, controls for audio/geometry, frontend module split or global CSS/listener overhaul.

The donor supplies useful paired-button/status styling and in-place updates, but its `detChoices(i)` checks only `!!EN[i]`; transplanting it unchanged would retain the mixed-state bug. Keep Austin's `qmPlace`, hover/click tap guard, below-placement CSS and enlarged preview behavior (N12). No standalone Superdesign/visual redesign is needed for this small control change.

## P07a draft integration boundary

At the comparison pin, `applyDet` (2867) updates both live `EN` and owner `EDITS.enabled` for every affected member, even when the value already equals `EN`. `loadReview` merges owner pending flags over fetched values (2787). `saveAndRender` copies the owner payload, retains job/view generation, acknowledges submitted maps and additions against their owner, and withholds rendering when newer edits remain (2964–3034). P02 should enter that existing setter path, not write only `EN` or bypass drafts through DOM events.

Do not add a shortcut that returns early when the requested value equals live state: explicit Blur on untouched true rows is deliberate output intent. P07a owns the distinction between untouched baseline, pending same-value intent, acknowledged repeat/no-op, snapshot acknowledgement and newer writes; P02 must reuse that final owning interface. The observed comparison establishes same-value capture and newer opposite-value preservation only. It does not establish every same-value-during-pending race, equality-based ACK behavior or sparse acknowledged-repeat contract; those require P07a's owner/version tests. Keep report metadata unchanged and do not introduce a second competing saved baseline/acknowledgement store inside P02.
