## Minimal source change map

Keep the change in ordinary emitted review JS and local CSS, plus owning tests/browser/server fixtures under `tests/`. The exact proposed new names below make the implementation concrete; they are proposed adapters, not interfaces already present on the standalone base.

1. Extract the existing grouping loop without changing its decisions into `reviewDescriptors(rows)`, and retain complete `REVIEW_META={sections,byId}`. Use descriptors `{id,category,realCategory,zone,representative,members}` and sections `{category,zone,cards,ids}`. `category` retains the section/action identity (`zdrop` for zones); `realCategory` is `representative.category` for all descriptors. Zone descriptors explicitly use `[id]`. Keep `TRKMEM`/`ROWCARD` as P02's existing owner maps. This shape aligns with the later P09 metadata seam while preserving the zone real category missing from that seam.
2. Introduce one view-local `REVIEW_FILTER={jobId,viewGen,type:null,output:'all'}` pair of selector values, with Show all defaults; `null` means All detected types and output values are `all`, `blur`, `visible`. Proposed DOM IDs are `reviewType`, `reviewOutput`, `reviewFilterReset`, `reviewFilterStatus`, `reviewFilterEmpty`; mark zone details and category sections explicitly. `setReviewFilter(type,output)` clears selection/menu and invalidates an outgoing review marquee, then calls `refreshReviewFilters()` locally. A same-view metadata reconstruction may retain a valid type; a new `openJob` always resets it. Do not persist filters in `REVIEW_DRAFTS`.
3. `reviewMatches(descriptor,type,output)` combines real-category equality with any-enabled/any-disabled effective member membership. Cache only derived blurred/kept aggregate counts if useful, tied to the current metadata/EN; no copied decisions. Counts scan complete descriptors once per transaction, never once per changed row. Type options preserve ordinary category encounter order, appending zone-only categories in first encounter order. Labels use `CATDN[cat]||cat` through `detLabel`; use native option values or escaped data attributes, avoiding category interpolation into JS/CSS selectors. Unknown/custom categories must not break quoting or action scope.
4. Reuse the later combined seam's small transaction pattern: proposed `DET_BATCH`, `DET_DIRTY`, `finishDetChoices()`, `applyDetBatch(ids,on)`. Keep `applyDet(i,blur)`'s deliberate setter behavior and row/group semantics. Dirty cards refresh once, the editor refreshes once, then filter counts/view refresh once. `setAll` snapshots all ordinary section IDs for its category; `setAllZd` snapshots all zone IDs; selected bulk snapshots explicitly selected currently matching/layout-available IDs before any mutation. This fixes the required hidden-member scope without importing the scheduler.
5. Update cards/section shells in place; do not rebuild `review`, `beslot` or the editor. Preserve the zone `details.open` choice when hiding a zero-match section and restoring it. On live changes prune no-longer-matching selections, and on zone close prune its IDs without resurrection. Marquee must skip hidden/closed/zero-layout cards and reject stale job/view/gesture completions; keep button exclusion, touch scrolling and Escape. Filtering must not mutate `EN`, any draft, fresh manual additions, playback or an unfinished **editor** gesture.
6. Before hiding content, capture whether the active element belongs to a disappearing review control/card/section. Move it to `reviewOutput` only in that case and announce the match count. A still-matching focused card retains its exact node/control; editor and unrelated focus stay put. Explicit selector/reset actions retain their own focus. Keep reset, save status/action and editor reachable for empty views.

No root ruling is needed on the approved behavior. Naming above is an implementation proposal. The unresolved root decision is execution allocation; the playback validation boundary below also needs to be retained explicitly in the dispatch.

## Required behavior oracles

- Group first, then filter. The approved seven-card fixture is A(face `[true,false,true]`), B(face true), C(plate `[false,false]`), D(plate true), E(email false), Z8(zone face false), Z9(zone plate true). All=7; Blur=4 (A/B/D/Z9); Visible=4 (A/C/E/Z8). Face=3/2/2 and Plate=3/2/1; Email+Blur=0. Repeat with A's representative false and pending flags opposite fetched flags. Mixed cards appear once in either matching view and actions still cover all members.
- Main status is **N of T cards match**, including collapsed zone matches. Each option count applies only the other selector. Category badges count matching ordinary groups; zone summary counts matching/total independent rows. Distinguish no detections, no matches, and matches only inside closed zones. Retain the approved mixed-overlap helper and category/zone bulk-scope explanations.
- Face+Visible may show A and Z8, but ordinary Face bulk still includes hidden B and excludes zones. Zone bulk still includes hidden Z9 and excludes ordinary groups. Selected bulk never follows a changing iterator into newly matched targets.
- Filter/reset causes zero detection/report/mediainfo/editor/save/render requests, no `loadReview/openJob/loadBoxEdit/showPanel` calls, no EN/draft mutations, and no editor remount. Normal ongoing polling/playback requests must be distinguished from filter-induced requests. Thumbnail behavior remains the base's owner.
- Held save/newer opposite choice, failure/retry and A→B→A retain P07a value-equality and job/view ownership. Old callbacks cannot change current counts/selection/focus. Unsaved manual additions lacking report row IDs remain drafts, not counted cards.
