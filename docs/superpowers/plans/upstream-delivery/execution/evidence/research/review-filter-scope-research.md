# P15 ordinary review view-filter scope

Status: source-only research complete, 2026-11-17. No product changes or UI execution. Ordinary review already groups detections and offers category output actions, marquee selection, video/editor navigation and enlarged originals. It has no detection-type or output view filter. Filtering changes presentation and thumbnail eligibility; explicit Blur/Keep visible actions continue to own output changes.

## Smallest proposed P15 contract

**What / why / when.** Add labeled native **Detection type** and **Output** selectors, a **Show all** reset and a concise live count/helper beside the current review controls. This lets someone find a category or kept/blurred appearances without changing output or navigating away from pending work. Implement after the final reviewed P02 interface, against P07a's draft owner. Coordinate with P09 if present, but do not require P09, O01, training or new tools/frameworks. Existing categories, layout, preview and editor remain sufficient.

1. **Complete card metadata, separate from presentation.** Build one transient descriptor per existing ordinary group and one per independent dropped row: representative/card ID, real category, ordinary/zone section and complete existing member IDs. Preserve all report rows and the P02 member-to-card lookup if available. This is derived display metadata, not another decision store. Do not filter rows before grouping, reconstruct membership from mounted cards, regroup on output changes or drop excluded entries. Ordinary group mutation remains `TRKMEM[i] || [i]`; dropped descriptors always have exactly `[i]`, regardless of matching people/tracks elsewhere.
2. **Effective choices.** Read each member's live `EN` value after P07a's pending overlay, not fetched `enabled` alone and not `EDITS.enabled` alone. `loadReview:2783–2787` overlays pending flags, including explicit false; `applyDet:2867–2875` writes live `EN` and pending owner state. Use the same boolean interpretation as the final P02 aggregate. Untouched enabled rows are valid blur output. Do not call setters to initialize/filter and do not remove keys from `EN`, pending maps, manual additions or editor state.
3. **Selectors and predicates.** Detection type is **All detected types** plus each real category present in the complete metadata, displayed through `CATDN[cat] || cat`; preserve the existing category order and escape inserted names. Include categories present only in dropped rows. Output is **All outputs**, **Includes blurred appearances**, **Includes visible appearances**. Type and output combine with AND. For members `M`, blur membership is `any(EN[m] is true)`; visible membership is `any(EN[m] is false)`. A mixed card appears once in each applicable output view, with its complete member scope and P02's truthful mixed state. A filter never limits a card action to its matching members. The helper states **Mixed groups appear in both output views. Filters only change the view.** No extra mixed/handled/pending selector is necessary.
4. **Counts.** Count each ordinary group once and each dropped row once, from full metadata, regardless of mounting, scroll position or collapsed details. Main status is **N of T cards match**, where T is every ordinary group plus every dropped row. Each selector option shows its matching-card count under the **other** current selector, ignoring its own selected value. Thus mixed cards contribute to both output options and those option totals may exceed the All total. A category heading badge counts only its matching ordinary groups; the zone summary gives its matching/total independent cards. The two section subtotals sum to the main N. Do not call counts visible/mounted counts: a matching zone card may be inside collapsed details.
5. **Zone section.** Apply type predicates using its real category and output using that row's effective flag. Keep the existing separate section and initial collapsed default. Preserve its open/closed choice across local filtering; never open it merely because it contains the only matches. Hide the section when it has no matches, retaining its collapse choice for restoration. If only collapsed zone cards match, status says so, e.g. **2 matching cards are outside your zones; open that section to inspect them**. Keep P02's neutral/truthful zone summary; enabling a dropped row must not imply a permanent “NOT blurred” state.
6. **Empty views.** Zero matches means a small **No cards match these filters** message beside **Show all**; keep selectors, existing save status/action and active editor available. Hide empty category grids/headings and disable/remove no-op view-specific actions. Distinguish zero matching cards from a report with no detections and from a report whose matching cards are in closed details. Resetting filters changes no choices and does not save/refetch.
7. **Live membership and focus.** Recompute affected group aggregates/membership after an existing output setter transaction, including non-representative editor removal, then update view/counts once per action/bulk batch. The current card disappears immediately if it ceases to match; do not add a pinned-card exception. When the focused control stays in a matching card, retain P02's in-place focus behavior. If the focused card/control becomes hidden, move focus to the **Output** selector and announce the new match count. Do not steal focus from an editor/control elsewhere merely because some card disappears. Explicit selector/reset actions keep focus on that control. Use existing `role=status`/polite feedback and native keyboard controls, with no global shortcuts or redesign.

Concrete proposed fixture: ordinary A(face `[true,false,true]`), B(face true), C(plate `[false,false]`), D(plate true), E(email false), plus independent zone Z8(face false) and Z9(plate true). There are **7 cards**, not 10 member rows: All outputs=7, Includes blurred=4 (A/B/D/Z9), Includes visible=4 (A/C/E/Z8). Under Face: All=3, Blur=2, Visible=2. Under Plate: All=3, Blur=2, Visible=1. Email+Blur has zero matches. The overlap is intentional. Keeping A in Blur view removes it; blurring A in Visible view removes it. Every action still affects all three existing A members.

## Selection and bulk scope

Filtering and collapsing are presentation operations; output actions need explicit targets:

| Action | Target contract |
| --- | --- |
| Card Blur / Keep visible | Its complete pre-existing group; dropped card only its row. Includes member states that did not independently satisfy the output predicate. |
| Ordinary category bulk | **Every ordinary group in that category**, including filtered-out or unmounted cards, per P09's whole-category contract. Never include dropped rows with the same real category. |
| Outside-zone bulk | **Every independent dropped row**, including filtered-out/unmounted rows and rows in closed details, per its existing separate scope. Never include ordinary groups. |
| Selected-card bulk | The snapshot of explicitly selected, currently matching/layout-selectable card IDs, each with full membership. Filtering creates no selection. |

Make category/zone scope explicit near their existing buttons, e.g. **Category actions affect all face groups, including filtered-out groups** and **These actions affect all outside-zone detections**. “Keep all visible” describes requested output, not a promise to target only displayed DOM. Do not silently adopt the donor's matching-only bulk behavior. For the fixture, Face+Visible displays A and Z8; ordinary Face bulk still affects A and B, while zone bulk affects Z8 and Z9. They remain separate controls.

Explicit filter/reset changes clear the current marquee selection and menu; no latent selection survives a temporary hiding operation. On live output refresh, prune selected IDs that cease to match and remove their highlight/menu count; on bulk action, snapshot targets first, perform all setters, then clear/refresh once. This prevents earlier changed cards from altering the remaining targets during iteration. P09 may unmount a still-matching selected card without removing its ID; selected actions use its complete metadata, never query its DOM. Do not select newly matched/unmounted/closed-details cards automatically. Marquee hit testing must skip filtered/closed cards; retain touch scrolling, button exclusion and Escape clearing. Closing the zone section prunes its now-unavailable selected rows; reopening/filter reset never resurrects selection. Job/view changes clear selection.

## Draft/editor ownership and P09 seam

Filter state is a tiny view-local pair bound to `{jobId, VIEW_GEN}`. New `openJob`, including A→B→A, resets to Show all. Same-view metadata reconstruction, if independently needed by an existing action, can retain valid selectors; a no-longer-present type resets to All. The filter event itself never calls `loadReview`, `showPanel`, `loadBoxEdit`, `openJob`, `saveAndRender` or fetch. Do not store filter choices in the report, draft decision maps or a second saved baseline.

P07a owns page-local job drafts, pending overlay, editor/manual/audio edits, acknowledgement and stale-view rejection (`2080–2115`, `2150–2170`, `2983–3038`). Preserve that owner and final P02's setter/aggregate interface. Filter changes must retain the active editor DOM and `BE` object, selected box, geometry/times/additions, unfinished ordinary editor gesture, playback, audio spans/baseline/loading and pending HTTP ownership even when the associated review card is hidden. The video/editor remains an unfiltered output editor. Its own existing Remove blur still changes output and can therefore change card membership; its row-local/group scope and `BE.sel` clearing remain P02's contract. Unsaved manual additions without report row IDs remain editor drafts and do not become invented review cards/counts. Do not import the donor's plate drag gate or remount the editor merely to filter thumbnails.

On job changes, leave P07a's existing video pause, fetched-display cleanup, pending-draft retention and audio baseline behavior intact. Old owner acknowledgements can reconcile their job's drafts but cannot refresh another view's counts, selection, focus, queue or editor. The source pin alone does not prove every acknowledgement race; P15 must use the final owning interface and its tests rather than invent sparse/dirty logic.

A sufficient future P09 hook is conceptually `refreshReviewVisibleSet({jobId, viewGen, matchingCardIds})`, called once after local filter/output refresh. IDs include the complete matching set, even unmounted or currently collapsed; existing section/viewport visibility further constrains actual scheduling. P09 owns intersecting that set with layout/viewport eligibility, mounts, queued/in-flight work, cancellation/stale results, retries and request bounds. The hook cannot mutate choices, reload metadata, remount editor/audio or save/render. Coalesced callbacks capture job/view and no-op if stale. Without P09, hide/show existing cards locally and retain existing image bindings/retries; do not claim that this cancels already-issued image requests or reduces full metadata cost. Avoid per-setter full-list scans during bulk: update affected aggregates through P02's derived membership index, snapshot action targets and perform one count/view/queue refresh per batch. No large-list latency claim follows from this design.

## Future implementation checks and limits

These are recommended P15 gates, **not tests executed by this research**:

- Actual emitted-JS predicates/counts: the seven-card fixture above; mixed representative true and false variants; category/person/track overlap, unknown/custom category, category existing only in zone rows, no detections, zero matches, closed-zone-only matches, all output values. Verify counts from complete metadata when only a page is mounted and keep matching unmounted rows recoverable.
- Effective-state ownership: fetched true+pending false and fetched false+pending true; same-value explicit P02 action, editor row-local removal and representative group removal. Filtering/reset must cause zero detection/report metadata/save/render requests and no changes to any draft/EN/non-output fields. Thumbnail scheduling requests are the distinct P09 owner; do not call them metadata refetches.
- Selection/actions: filtering/reset cannot leave hidden IDs actionable; automatic disappearance prunes selection; remaining selected membership survives P09-only unmount; bulk snapshots targets before refresh. Category actions include filtered-out/unmounted ordinary groups, exclude zones; zone bulk includes all dropped rows, excludes ordinary groups. Card actions preserve every existing group boundary and complete-member scope. Closing/reopening details creates no latent selection.
- Browser: real native selector pointer/keyboard changes, retained filter focus, same-card focus retention and deterministic Output-selector fallback when the focused card leaves; polite counts, clear mixed overlap/scope explanation, empty-state reset and 390px layout. Existing marquee/touch/Escape/enlarged preview/mobile help remain usable. No browser evidence is claimed here.
- Active editor: open it, set pending geometry/times/manual/audio, select/edit a box and filter its card out/in. Assert identical editor node/object, playing/scrub/selection/draft state and no editor fetch/rebuild from the filter. Exercise a pending ordinary gesture separately from a completed output change. An actual Remove blur retains its existing mutation/selection behavior.
- Owner races: A→B→A defaults Show all while restoring job-owned pending choices; late metadata/thumbnail/filter callbacks cannot alter the new view. Filter during an in-flight save; old ACK, failure/retry and newer pending edits preserve P07a ownership. Assert filter changes alone never submit edits or trigger an allow-list confirmation.
- Hidden decision round trip: choose mixed/group/dropped outputs, hide them, save through the real owning transaction, fresh reopen and verify stored flags plus unchanged geometry/audio/manual data; render a bounded synthetic clip and inspect selected/kept/unrelated regions. Respect the separate P06D/C01 report roundtrip prerequisite described in task 20; a source-only P15 design cannot prove post-render row preservation.
- Implementer runs P15's required targeted tests/build/S03 browser cases when delivering. Coordinate request-bound tests with P09; do not duplicate its broad benchmark or claim metadata pagination from DOM filtering.
