## Proposed mounting model and honest bounds

Actual `.grid3` is `repeat(auto-fill,minmax(175px,1fr))`, 9px gap (`1763`), inside a max-width 1560px app. Each category has a heading/actions followed by its own grid; dropped rows are in a separate initially collapsed details/grid before ordinary categories. Cards have variable text, group scope and paired actions; images currently have only `max-width:100%` (`1771–1786`). Flat fixed-card offsets or `display:none` around every retained card do not fit this layout.

Use **one global budget starting at 64 mounted cards across ordinary and open zone sections**, not 64 per category. Retain category headers and zone summary/bulk controls. Within each section, mount a contiguous set of complete grid rows, with a full-width before/after spacer for omitted rows. Multiple intersecting sections share the budget. Implement row wrappers using the existing column width/gap rules, with no individual offscreen card placeholders. Normal mounting rounds down to complete rows where possible; partial final category rows preserve their empty trailing cells. Do not generate all row wrappers: retain row offsets/heights as numbers in metadata and only mount wrappers for active rows.

Reserve a consistent thumbnail well before issuing requests (proposed 112 CSS px high, width of the existing card content, `object-fit:contain`). Preserve text and actions without truncation; large originals remain available through `zoomDet`. This is a local sizing proposal requiring root approval/actual browser evidence, not measured tuning. Image arrival then cannot change row geometry. Row height is the maximum natural card height in that row. Use conservative estimated heights for unseen rows and measured heights for mounted rows, with prefix offsets in JS. A `ResizeObserver` on mounted rows/container and one coalesced animation-frame refresh update column count/row heights/spacers; preserve the first visible group and pixel offset when estimates change. Account for margins/gaps exactly once. Width change invalidates width-dependent row measurements and repartitions the same ordered IDs; do not fetch metadata or rebuild the review/editor.

A scroll refresh locates rows intersecting the actual viewport from section offsets/prefix heights, then admits nearby forward rows up to **at most one viewport of prefetch total** and the card budget. Visible rows take precedence; prefetch may be smaller or zero. A large scrollbar jump directly selects the destination rows without sequentially mounting the intervening collection, then corrects estimated geometry against measurements. Keep the scrollbar extent for every omitted row, including the last row, so the last group remains reachable. Below-viewport review initially need not issue thumbnails. Closed zone details retain descriptors/summary only: zero zone cards, queue entries or retained image URLs; opening inserts its height/window and closing removes its layout height and work.

Keep an already-focused card's actual subtree until focus leaves it; never replace/move its focused ancestor to reuse a node for another ID. If it falls outside the current window, retain **at most one additional focused card**, with empty structural cells/spacer partitions preserving that row's position. Do not retain all previously focused/selected cards. Normal 64 plus this explicit exception means at most 65 card/image elements, not an unconditional 64 bound. A retained focus row may require splitting the omitted region into an extra spacer pair. Once focus leaves, retire the exception. If resizing changes its row, preserve the subtree and restore the same focused control only if browser reconciliation requires it; verify native focus and scroll behavior rather than assuming DOM moves preserve focus.

Provide two native, contextually named boundary controls around the active range (previous/next review cards with range/total feedback). Activating one mounts the adjacent range and focuses its first/last actual action as appropriate; it never changes output. This is the smallest proposed explicit keyboard path across unmounted content, while scrolling/jumps continue to work. Root must rule on these controls before implementation. Preserve Tab/Enter/Space, pressed attributes, contextual group names and visible focus. Do not claim screen-reader access to omitted card subtrees: expose total/range and a polite status, and test the boundary controls. A focus pin alone does not make every unmounted group keyboard reachable.

**Cardinality limits:** full detection metadata, group/member indexes, row measurements and explicit selected-ID set remain O(rows/groups). Category heading/action/grid shells remain O(categories), with a constant number of spacers per participating section; this is not a constant-total-DOM claim for reports with thousands of distinct categories. There is no O(groups) hidden card/image/row-wrapper tree and no retained card HTML per group. Object URLs/decoded mounted images are bounded by mounted targets; browser cache, allocators, native server work and complete metadata are separate costs. If a supported viewport can intersect more than 64 actual cards, strict 64 cannot show every visible card. Record that concrete layout conflict and obtain an evidence-based internal budget change; do not silently leave holes or call 64 tuned. Tall/zoomed/long-text cases also need offset/anchor verification.

## One visible-first thumbnail queue

Create one scheduler for the mounted review instance, capturing `{jobId, viewGen, rootNode, token}`. It owns only mount/layout listeners, the desired matching/layout set, pending requests, active thumbnail controllers, retry timers and mounted image URLs. `ownsView` plus scheduler-token/root identity protect against same-job review replacement without a generation increment. Scroll/resize/details events never call `loadReview`, `openJob`, `showPanel`, `loadBoxEdit`, save or render.

Use existing browser primitives: `requestAnimationFrame`, `ResizeObserver`, `AbortController`, `fetch`, `Response.blob`, `URL.createObjectURL/revokeObjectURL`, image load/error and ordinary timers. No framework, worker pool or general asynchronous task abstraction. Mount images without eager network `src`. Admit visible targets before nearby targets; deduplicate by descriptor/binding identity. On refresh replace/reprioritize the small desired queue, remove obsolete pending/retry entries and abort no-longer-eligible active fetches. Recheck eligibility immediately before dispatch. The focused exception can remain mounted with an unavailable/previous image but does not expand offscreen prefetch eligibility.

**Four slots mean four unsettled browser fetch/body operations**, from before `fetch` through full blob consumption or rejection. Headers alone do not free a slot. Aborting marks an operation obsolete immediately but releases its slot only in its actual settlement/finally path. A replacement view mounts metadata/cards immediately but waits on the disposed scheduler's active-operation drain before dispatching new thumbnails; never reset active counts and start four more while old browser operations remain live. Native browser abort is the transport primitive, not proof Flask/OpenCV stopped. Native server decode may overlap replacements after browser settlement; neither four server workers nor four native decodes is promised. The bound excludes polling, metadata, media, compare and user-requested `detframe` lightbox traffic; classify each separately in evidence.

Before blob publication require current job/generation, current scheduler/root, still-eligible descriptor, identical connected target node and identical binding token. Every async continuation/timer/load/error applies the same checks. A stale blob is discarded without an object URL; a URL created before a race is revoked. Successful assignment releases the browser network/body slot; image load/decode is a separate phase and stays fenced. Revoke URLs on replacement/unmount/error/disposal, clearing obsolete image handlers/src; do not build an offscreen blob cache. Keep URLs until the mounted image is retired to preserve normal image interaction. Image errors return to the same bounded queue, not an eager direct URL assignment.

Preserve the existing three retry delays **600/1200/1800ms** (`thumbRetry:2911–2916`) for actual fetch/body/image failures, with a single shared attempt budget per descriptor/binding for this view: initial try plus at most three retries. Cancellation is not failure; scroll-away/remount must not reset a failed descriptor's budget. Timer delay begins after failure; timers hold no slot, recheck owner/eligibility and enqueue rather than bypassing the four slots. When eligibility disappears, cancel the timer and retain bounded retry state for later eligible reentry. Prefer fresh visible attempts ahead of ready retries, and visible retries ahead of nearby prefetch, so one broken image does not monopolize a slot or endlessly renew work. At exhaustion show a neutral image-unavailable state while Blur/Keep/editor/save remain usable. Preserve current status coverage initially rather than importing a speculative HTTP taxonomy, metadata recovery or decode deadline. A hung live transport can occupy a browser slot until abort; no new timeout duration is justified by this source-only report. Teardown/large-jump abort must be tested during both headers and body.

## Selection, drafts and disposal

Scheduler disposal never clears `EDITS`, `REVIEW_DRAFTS`, `EN` choices, editor/media/audio state or another job's edits. Late save acknowledgements still reconcile their captured draft owner, and never refresh another job's selection/mounts/queue. Existing job-switch video pause and draft trimming remain P07a's responsibility. Page-hide cleanup must not disturb legitimate drafts; any resume reuses the same view's metadata/choices.
