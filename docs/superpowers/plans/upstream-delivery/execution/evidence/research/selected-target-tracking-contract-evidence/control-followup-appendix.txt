
## Focused source-only follow-up: target controls independent of geometry rows

2026-11-17. **New recommendation for root decision; not adopted and not implemented.** This appendix compares a smaller alternative to the preceding anchor proposal. The original **45,313 bytes**, SHA-256 `9217d6cb3b941ec6872eb77f8ff4539e921b3b4c7cb8eae7da43a66d697fc65a`, remain an exact byte prefix. [Integrity proof](selected-target-tracking-contract-evidence/control-followup-integrity.json) records original/final hashes and prefix verification. The earlier proposal is preserved as a proposal, not relabeled as adopted. Only existing C exports and adopted O01 boundaries were consulted; no new product export, broad re-audit, runtime, test, model, browser or benchmark ran.

**Recommendation:** put one current optional target-control mapping in the existing raw report, keyed by an immutable target ID. Keep supported current geometry only in existing detections. This is simpler overall than anchoring control state to a geometry row: it removes anchor transfer, unique-anchor repair and the artificial no-support-trim restriction, while adding one direct record lookup and a bounded row-to-target reference. A report-level current control mapping is not a parallel observation registry, database or history. It remains part of the same report.json transaction/publication owner. The initial report's insistence on storing all control state in a sample payload was unnecessarily restrictive; O01's per-Detection owner applies to sample evidence, not a requirement to attach geometry-independent current controls to a surviving sample.

### Small alternative schema, identity and zero-supported-sample behavior

Proposed names are private/provisional:

```text
# One additive mapping only in a provenance-capable optional report.
optional_targets = {
  target_id: {
    version:1,
    track: report_local_integer,
    creation: {source_binding,timeline_eq,policy,seed_index,
               immutable_seed_creation,requested_interval,target_kind,initial_intent},
    interval:[lo,hi],
    keyframes:[index,...],          # current supported keyframe references only
    boundaries:[index,...],
    choice_spans:[{lo,hi,choice},...],
    gaps:[{lo,hi,status,origin,reason},...],
    last_correction?:{request_id,request_eq,committed_effect_eq}
  }
}
# Existing Detection optional immutable payload / encoded row adds:
policy_evidence.target_id = target_id
# Existing track remains grouping; current cbox/aoff/index/evidence remain in rows.
```

Use one immutable client target ID created once before initial launch and retained for explicit retry. The existing manualId generator/format can be reused, but the wire field is `target_id` and lookup is explicitly in this mapping; regular `manual_id` row lookup remains a separate typed interface. Do not overload ordinary P07 manual-row replay by inventing an anchor row. Initial O02 creation compares the mapping's immutable submitted creation before any new work and returns a mutation-free acknowledgement for an identical already-published creation, without restoring later corrections/Keep/Blur. A conflicting creation under the same target ID is409. This reuses P07's immutable-creation/replay-first principle at the existing O02 transaction adapter; it is a new target-control lookup/validation branch, not functionality already supplied by `_valid_manual_creation`. Regular manual additions retain their exact current row/manual_id/manual_creation behavior.

`immutable_seed_creation` can use the already validated seed box/offset/time facts needed for request equality. It is immutable request evidence, not another current geometry sample. Current mutable keyframe geometry lives only in its supported Detection row; `keyframes` contains indices, not a duplicate geometry history. A keyframe index must resolve to one supported same-target row at that frame. Trimming a keyframe out of the allowed interval removes that current index/row; the initial request creation stays immutable for replay. No per-frame observations are stored in optional_targets. Samples are persisted once in detections; only coalesced unsupported intervals and sparse current control choices/boundaries/receipts live in the mapping.

Current optional target identity becomes the immutable report-local `target_id`; `track` is its current report grouping assignment, not the immutable identity. A legacy track number without a target record is still just grouping. Neither target_id nor track grants source access or validates pixels. P10's current source_ref/epoch remains a separate revocable live source capability; the record's immutable source_binding/timeline relation must be re-admitted after reopen, and source replacement does not silently move the target onto another input. No portable old source_ref, whole-video hash, automatic cross-source rebase or durable HDR mapping is introduced.

A target may have `interval:[50,70]`, `keyframes:[]`, no supported detection rows and `gaps:[{lo:50,hi:70,status:"lost",...}]` while retaining its immutable target_id, initial/current intent and single receipt. This is a valid current all-gap target, not deletion. Trim/retrack may produce this state without keeping an out-of-interval seed or fabricated cbox. The ordinary render subset then contains no geometry for that target, so explicit Blur remains intent and paints nothing there. A later exact correction at frame60 adds one supported row/current keyframe and can retrack its permitted segment; unproved surrounding frames remain gaps. Explicit target deletion is still an explicit action that removes the control record and its rows in one transaction, not an implicit consequence of zero samples. The all-gap target can save/reopen/render/export without a new gate.

The mapping therefore removes the original proposal's unique-anchor/manual_id-on-seed requirement, anchor transfer and no-support-trim restriction **if root adopts this alternative**. It does not change the original source findings or make this appendix adopted. It preserves the original generic box-only/exact-source/support-origin/stop-on-loss/correction-span contracts and raw-index stale-choice safeguards. Replacing geometry can still shift raw indices even when target control has a stable ID; ordinary row-choice contexts remain necessary.

### Same bounded correction replay, now attached to the target record

Keep exactly the existing proposed single-latest-receipt and `prior_correction_id` contract. Change target lookup in CorrectionRequest to `{target_id}` with its current track derived/validated from the record. The target's source/timeline and affected geometry/control equality are still checked; mutable choice_spans/materialized output/audio remain excluded from that geometry projection. Preserve the existing receipt ID, exact submitted request equality and committed-effect checks; no counter or history is added.

The A-response-lost → B-correction-committed → delayed-A-retry proof is unchanged: B replaces the one current receipt; delayed A carries an obsolete prior_correction_id, returns409 without model work or publication, and preserves B. If B is a no-op/equal result the predecessor check still protects it. If A remains the matching latest receipt/effect under the current source/timeline, exact A replay succeeds without mutation. Initial target creation replay remains a separate mutation-free immutable-creation acknowledgement and never restores A over B. An all-gap record retains the receipt even with no row, which is another simplification over a geometry anchor.

### Opaque fields: equality is a fence, not preservation

The earlier replacement step's phrase “unknown affected row fields are compared/preserved” needs a concrete restriction: **comparing an opaque field for equality does not preserve it when the entire source row is subsequently deleted.** Neither copying a same-index value into an arbitrary new sample nor retaining all old rows as history is acceptable.

The smallest safe first-delivery rule is an explicit optional-regeneration field ownership table. For every affected generated row that would be removed or rewritten, the adapter must know which fields it regenerates (box/index/timing/offset/method evidence and known optional target reference), which fields it derives from retained target intent (output_choice/enabled), and which it preserves through an explicit semantic mapping to the same frame/keyframe. Known unsupported shape/person/other metadata cannot be dropped merely because the optional engine emits boxes. Unknown top-level report fields and rows outside the replacement remain raw-preserved by the latest-document merge.

**If any field or nested metadata on a row that will be deleted/replaced has no defined regeneration/preservation owner, reject the whole new correction/trim/split replacement before publication.** A current, unchanged but unsupported extension may return `422 unsupported_regeneration_metadata` with its field path; an extension/context added or changed since admission returns409 `target_conflict`. Preserve the complete report and all pending drafts. Validate this once before expensive work and again at publication. A known unchanged protected endpoint row that is retained verbatim needs no invented regeneration rule; replacing that row later is subject to the same gate. Do not infer that every opaque extension is geometry-neutral, normalize it away, transplant it to a lookalike frame, or retain redundant old sample histories to avoid the decision.

Examples: an affected row's unknown `custom_mask` value that matches the captured baseline still blocks box regeneration if its owner is undefined; an unknown field on an unrelated untouched row remains byte/value-preserved; an opaque additive control-record key can be retained verbatim when only recognized sibling controls change, but rewriting/removing a structure containing an unknown field requires a defined owner or rejection. Pure same-receipt replay that writes nothing does not need a regeneration owner, but still must satisfy its current source/effect/context contract. This is deliberately conservative, optional-only and does not reject ordinary legacy save/render merely for carrying opaque metadata.
