## New O02 proposal: narrow capability, seed and result interfaces

Use O01's provenance-capable optional report, with an additive `selected_tracking: 1` capability inside its existing optional format marker. This is a codec feature level, not another report version/history system. Ordinary/legacy reports do not enroll merely by opening or clicking Track. With capability absent or request option absent/off, call the existing tracker and writer unchanged. A previously optional report switched off retains its saved evidence/corrections/choices; O02 unsupported rows never become legacy frozen masks on a policy toggle. Off does not imply historical provenance can be invented for ordinary reports.

First delivery is review-only **generic region boxes**, accepting intent labels `region`, `plate` or `text` as user selection semantics; labels never select the person engine or establish physical outline/identity. No quad/poly/mask input is silently reduced or propagated: reject unsupported shape clearly or ask the user to explicitly choose a box before launch. Zero YOLO/OCR results do not prevent a valid manual box seed. Skip PersonDetector construction on this optional path; legacy tracking keeps it.

```text
# Proposed optional additions at the existing /track_object boundary
{selected_tracking: 1, manual_id, box, t0, t1, t_ref,
 seed: P10SamplePrecondition, target_kind: "region"|"plate"|"text",
 intent: "blur"|"keep"}

P10SamplePrecondition = {source_ref,timeline_eq,policy,index,
                         canonical_s,observed_s,width,height,offset}
# offset == cum[index]; browser supplies no raw pixels/capture.

track_manual_region(..., person_det=None, *, strict_seed=None,
                    selected_tracking=None)
selected_tracking = {frame_lo,frame_hi,continuation_policy,target_kind}
# Existing return tuples remain exactly the no-option interface.
# Optional return value is request-local, consumed once into existing detections:
SelectedResult = {samples: [SupportedSample], gaps: [Gap]}
SupportedSample = {index,observed_s,source_box,origin,
                   method,raw_score,continuity_evidence}
Gap = {lo,hi,status: "uncertain"|"lost",reason,origin}
```

All consumed times/coordinates must be finite non-boolean values; indices are bounded integers. `box` is a meaningful nondegenerate source-space rectangle inside the admitted source; do not clamp a wholly invalid box into a new selection. Resolve the UI interval once to a half-open integer domain `[frame_lo,frame_hi)` using the admitted timeline: samples satisfy `t0 <= i/fps < t1`; require the strict seed index inside it. For the first frame selected by a nonaligned start use `ceil(t0*fps)` under one documented boundary rule. Validate floating boundary behavior; do not round seconds back into indices. Reject an interval containing no seed/sample. Preserve exact requested seconds in immutable creation; frames own subsequent sample coverage.

**Adopted P10 prerequisites:** coherent source-report selection, supported CFR/backend/time-origin policy, strict verified seed pixels, `source_ref`/timeline/dimensions/offset checks before model work and again before publication. Release the web verification capture before model work. Both directional initialization and NCC template use supplied pixels; existing capture owners verify their after-seed positions, with no nearby/tolerant fallback on strict failure. Source stamps are observed identity, not a content hash; same-observed-attribute external mutation remains a stated limit. No whole-video or seed-pixel hashing is proposed.

**Additional O02 requirement:** P10 verifies only initialization/priming; it does not certify the current later `_RevReader`/sequential samples. Every optional published sample needs a verified integer and observed timing/dimensions under the same policy. Forward iteration can validate sequential positions from the verified prime; reverse chunks must carry and verify integer indices, or call the same indexed primitive for requested integers. Any tolerant search/nearby read lacking this evidence is an explicit gap/failure, never relabeled exact. The first optional adapter uses one-frame cadence; it cannot stamp a sampled box over undecoded frames. Performance/backend practicality of that adapter is unrun. If the existing reverse reader cannot supply the required evidence, the delivery is blocked on its narrow adapter rather than claiming P10 alone solved it.

`SelectedResult` is worker-local output, not persisted duplicate observation storage. On commit encode each supported sample once as an existing dense manual Detection/row; encode coalesced gaps on its existing target anchor metadata. Do not persist an array of raw tracker histories or full frames. Metadata absence/corruption in a marked report supplies no support.

## Per-frame geometry, origins and conservative continuation

The **authoritative geometry** for supported frame `i` is that row's content `cbox`, with `aoff=cum[i]`; source-space box is `cbox+cum[i]`. Preserve finite subpixel geometry through optional conversion; do not silently truncate before the renderer's normal rasterization. Store `index=i` independently of mutable `t_start`; `last_seen`/confidence/span width cannot establish observation identity. Rows project to `t_start=i/fps,t_end=(i+1)/fps` for ordinary display only. Optional review/preview/render must use integer frame membership `[i,i+1)` before legacy ±.01-time inclusion, coverage and `_dedupe_dense`; otherwise end grace can cross into a gap. Existing rendering pad/drift/coverage are output choices, not location evidence. With per-frame aoff, same-frame scroll drift is zero. No optional temporal smoothing, padded ends, inherited frame support or widened weak-lock union.

Use the O01 immutable per-Detection payload and capability-gated encoder/hydrator. Proposed encoded payload additions:

```text
policy_evidence = {
  sample: {index, origin: "manual_seed"|"correction_keyframe"|
                           "visual_continuation"|"detector_observation"},
  geometry: {status:"supported", method, raw_score?, continuity_evidence?},
  target_control?: {...}  # exactly once on the existing anchor row, below
}
output_choice = "blur"|"keep"  # O01 materialized explicit intent at that frame
```

Source/timeline binding is report-level through P10's admitted selected source and target-control binding; do not copy a complete source descriptor/cum into every sample. A future detector observation records its genuine detector/frame and score independently from tracker continuation. O02 box-only continuation does not manufacture YOLO observations from successful tracker updates; OCR absence is irrelevant to accepted visual support. Manual/correction seeds are human-provided geometry for that single exact frame, not independent plate detector hits and not proof of future location. A tracker score remains raw method evidence, not a calibrated probability. O01 consumes these geometry/observation distinctions without treating the number of synthetic/continued rows as independent detector observations.

The optional adapter must mark the actual branches, not infer provenance from final tuple score: Vit weak union, frozen hold, NCC `_hold_rest`, person grace/anchor/reacquisition and decoder failure otherwise lose their origin information. Excluding the person path removes that helper's complexity from first delivery. Known zero-score held/weak outputs are unsupported. Upstream numerical .30/.15/.55/.80 and edge/scale heuristics are not accepted O02 thresholds.

Proposed minimal support progression per direction:

1. Verified manual/correction box supports its own frame immediately, regardless of detector/OCR availability.
2. A fresh decoded-frame tracker update can be a **candidate continuation** only with finite valid geometry, method success, finite method score and accepted continuity gates. A named experimental policy must specify score, displacement/scale/appearance/cut/ambiguity checks and their calibration. Finite geometry or a high score alone does not prove continuity. Existing source supplies tracker updates/scores and some heuristics; it supplies no accepted general cut/crossing detector or calibrated identity certificate. Those owners must be implemented/measured or explicitly remain unsupported.
3. A failed gate/read, weak/frozen output, suspected cut/occlusion/exit or ambiguous crossing makes an uncertain/lost interval. Do not render a mask there even with explicit Blur. Store reason independently of output intent. Coalesce adjacent equal status/reason intervals; no fabricated box is stored for missing geometry.
4. First conservative delivery stops automatic continuation in that direction at the first unsupported interval; the remainder up to the segment boundary remains a gap. Do not accept a later recovered score/string as proof of the same target. Resume only from a new explicit exact correction keyframe. Automatic reentry/reidentification is deferred. “Exit” is a reason for loss, not proof that nothing sensitive remains visible.

Until continuation gates are calibrated/accepted, this proposal authorizes only source-backed possible states, not a production reliability promise. Conservative stopping may still accept drift that a gate cannot detect; crossing/cut accuracy must be evaluated before workflow claims. A gap is allowed to remain unresolved/exportable. The user may correct, trim or explicitly create/select a broader region; no automatic broadening/freeze/person switch or compulsory queue.

O01 creation/copy boundaries remain mandatory: no optional declared defaults leaking through `asdict`; synthetic `_mk` objects get synthetic rather than copied observation identity; payloads immutable across coverage shallow copies; hydration restores evidence before recomputation; full report retains disabled samples/anchor/gaps; new args defaults do not leak into ordinary `_settings_dict`. Filter optional supported geometry before coverage/dedupe. No current codec performs this automatically.

## One current target record inside the existing report

Reuse the existing report-local integer `track`; keep `person=-1` and manual category for selected boxes. The current optional target is the report-local pair `(track, unique anchor manual_id)` interpreted under its immutable creation/source binding, never text or person overlap. The integer track alone in a legacy report is only grouping and cannot be upgraded into this target contract. A current P10 `source_ref`/epoch is a separate, revocable live source capability used to admit a request; it is not the target ID, a permanent identity or a portable reopen token. Reopening may establish a new current source_ref for the same report-local target only after the recorded source relation is re-admitted; source replacement does not silently transplant that target onto new pixels. Exactly one existing sample/keyframe row in the target carries `manual_id`, existing immutable `manual_creation` and `target_control`. All other samples already identify the group by `track`; there is no separate target table, database, registry or observation journal.

```text
target_control = {
  version:1,
  creation: {source_binding, timeline_eq, policy, seed_index,
             requested_interval, target_kind, initial_intent},  # immutable
  interval: [lo,hi],                          # current half-open frame domain
  keyframes: [{index, source_box}],            # current sparse corrections only
  boundaries: [index,...],                    # explicit continuity splits
  choice_spans: [{lo,hi,choice}],              # sparse explicit overrides
  gaps: [{lo,hi,status,origin,reason}],         # current coalesced unsupported runs
  last_correction?: {request_id, request_eq, committed_effect_eq}
}
```

`manual_creation` keeps its existing exact four-field shape/validation, with creation box/offset/seconds calculated from the strict seed. `target_control.creation` supplies immutable tracking-specific fields without changing P07 replay semantics. Both survive mutable keyframes/geometry/choice/trim. No raw pixels, capture, browser source_ref minted by a retired incarnation, or every old request/result is persisted as a portable capability. `source_binding` records the selected scan-source relation, reliable opened-source stamp observed at creation, dimensions/stream policy and timeline identity; an existing scan input_sha256 may be retained as evidence but is not newly computed/verified here. These are small equality facts, not a portable content certificate. After reopen re-admit it through P10, mint fresh current source_ref, and mark correction unavailable on unproved relation. Durable cross-source/HDR remapping is P17, not filename/text equality.

The anchor is a current report record, not necessarily the original raw array index forever. If replacing/trimming removes its sample, transfer the **single** control/immutable-creation record to a surviving supported keyframe row within the same atomic transaction. Keep it unique. Initial delivery must reject trimming away every keyframe/support row; removing the target altogether is a separate explicit deletion, not a pretend gap with fake geometry. This limit avoids control-only pseudo-detections/null cboxes and a second report schema owner. Trimming that would leave only a gap requires retaining one supported keyframe or explicit target deletion. Never copy the anchor's manual_id to every regenerated row.

`keyframes`/boundaries are sparse current user corrections; `gaps` store only the unsupported complement/reasons that has no geometry row. Supported samples are stored only in detections. Do not persist duplicate supported geometry history in target_control. Bound metadata by current interval/current keyframe count; replacement discards superseded generated rows/gaps rather than archiving them.

`initial_intent` is immutable request identity. Current target intent is that default plus sparse `choice_spans`; row `output_choice` is its O01 materialized projection. An explicit target/group Keep or Blur updates its chosen current interval and materialized rows atomically; a row/segment click adds a bounded frame-span override. This preserves explicit choices across gaps/regeneration, where there may be no row to hold them. Adjacent equal overrides coalesce; later explicit choices replace only their selected range, not a historical action log. Ordinary non-target rows keep O01's row-choice owner. Group representative confidence/choice never silently rewrites mixed target spans. Saving coordinates, retrying initial creation or changing policy does not reset current choices to initial_intent.

## Correction, split and retrack transaction

The following is a **new API contract**, not implemented in C or P10. Prefer optional `action: "correct"|"split"|"trim"` at the existing tracker route/status boundary; no additional worker registry. One tracker lease/Event/status continues to own an in-flight job operation. A private pure helper may compute span/merge equality inside the existing report transaction.

```text
CorrectionRequest = {
  request_id, target: {track, manual_id}, action,
  seed?: P10SamplePrecondition, box?: source_box,
  edit?: {keyframe_index | split_index | trim_interval},
  affected: [lo,hi],
  base: {source_ref,timeline_eq,target_geometry_eq,prior_correction_id}
}
```

`request_id` is an immutable client id reused for the same submitted request, with P07's bounded ASCII format. Canonical `request_eq` covers target/action, exact seed/box, affected domain, proposed keyframe/boundary/trim edit and baseline; changing payload under the same id conflicts. It never includes mutable current choices/audio. `prior_correction_id` is the current single receipt ID (null before the first correction), compared by value for a genuinely new request. It is not a history/counter or a source capability; it is the predecessor value of the existing bounded receipt. A matching same-request replay is checked before this predecessor check. Every committed new correction updates that receipt, even if its resulting geometry happens to be equal. This small precondition is necessary to reject a delayed old request after an indistinguishable/no-op newer correction without retaining old IDs. `target_geometry_eq` digests the current target's sparse keyframes/boundaries/interval/gaps plus each affected existing sample's geometry, immutable frame/origin/context and opaque additive fields. Exclude only materialized `enabled`/`output_choice`, target choice_spans and the single retry receipt. Preserve parsed opaque JSON compatibility; finite rules apply to consumed coordinates/timeline, not arbitrary additive metadata. Hash only the affected parsed projection; no full-report/video hashing, second parse or full-cum stringify for convenience. Timeline equality uses P10's owner.

**Affected span rule:** existing sorted keyframes and explicit split boundaries delimit independent segments. Inserting/updating a correction at frame `k` retracks only between its nearest existing protected keyframes/splits/window edges. Existing endpoint keyframes are fixed and retained. With only the initial seed, that can be the whole containing segment; after another keyframe, later corrections are bounded by those anchors. Publish/replace the interior plus the new/edited keyframe, never overwrite a neighbor keyframe. Do not blend forward/backward results into an unvalidated box: track outward from the corrected seed inside that interval, stop at unsupported gates, and retain endpoint geometry at the endpoint's own frame. Inconsistent endpoint approach remains a gap requiring correction, not a forced interpolation. The server computes affected from the immutable submitted baseline and compares it to submitted affected; the client cannot expand across protected anchors silently.

A split at integer `k` is a continuity boundary, not a new physical target/track. Preserve the existing target/intent. It retires any continuation whose proof chain crosses `k`; it cannot retroactively make a seedless far side supported. Keep explicit keyframes on both sides; regenerate only segments with an admitted anchor, otherwise mark the seedless side lost until correction. A geometry-free split may execute synchronously under the same report transaction; a later seed/retrack uses the same current target. `trim` changes only current allowed domain and clips rows/gaps/choice spans; obey the supported-anchor limit above. If the user wants a separate object with an independent target, explicitly create a new target rather than silently reassigning these samples.

Transaction sequence:

1. **Initial creation replay:** inside the existing latest raw report transaction first resolve the unique manual_id and immutable manual_creation plus tracking creation. Identical already-published creation is acknowledged without model work or restoring later choices/corrections; conflicting/multiple/missing creation is409. Existing P07 replay-first semantics remain. A replay-only ACK does not grant a new strict source or mutate geometry; any new correction/other strict delta still validates current source/context. IDs colliding with ordinary additions conflict rather than enroll them.
2. **Correction replay:** under report lock find the same target/unique anchor; require current source/timeline and target binding. If the single stored last_correction has same id/request_eq and its geometry effect still equals committed_effect_eq, acknowledge without work or rewriting choices. Choices/audio-only changes do not defeat this replay. Same id/different payload, changed geometry/effect, or an older request no longer represented by that single receipt returns409; it never replays destructively over later corrections. The receipt is one bounded result acknowledgement, not an unbounded journal. No automatic/background retries.
3. **Admit new work:** require submitted prior_correction_id to equal the current single receipt ID, then capture latest target geometry projection, current keyframes/affected span and strict seed, using existing `_edit_gate`/tracker/source/operation owners. Prepare source outside report lock and revalidate on reentry. Preserve captured Event; do not reuse an Event later cleared for another attempt. Decode/compute outside report lock; strict source/sample failure is distinct from ordinary tracker model fallback and publishes nothing.
4. **Publish once:** reacquire report lock; recheck job incarnation, source/timeline, operation/status/cancel, unchanged prior receipt ID and original affected target geometry projection. Read latest raw report; merge latest current choice_spans and audio/unrelated edits. Concurrent affected geometry/keyframe/split/trim/raw-context change yields409 with zero replacement. Unrelated geometry rows, choices/audio and harmless report epoch changes do not invalidate the targeted correction; unknown affected row fields are compared/preserved rather than silently discarded. An affected row with an unrecognized geometry-affecting extension is unsupported for regeneration until its owner is defined.
5. **Replace current span:** discard only superseded generated rows inside affected, retaining protected endpoint keyframes, outside target rows, other targets/disabled/unknown rows and their relative order. Insert new current supported samples at that position; clip/update coalesced gaps only within affected; update sparse current correction/boundaries and materialize effective output from latest intent. Transfer the unique anchor when necessary. Do not reset `initial_intent` or manual_creation. Publish report plus one new receipt with existing atomic_report under the same lock; notify P10/P08's successful publication owner only after success. Failed write advances no committed state and ACKs nothing.
6. **ACK/cleanup:** return current target/track and committed geometry baseline/affected interval/receipt identity. Existing owned-thread finally releases captures before source/work leases; failure/cancel/restart publishes no partial samples. P07/P10 deep snapshots clear only equal submitted values in the same draft/source/baseline family. Retain newer different corrections/choices/audio. Keep one uncertain submitted correction snapshot across lost ACK, and explicitly replay that exact payload before submitting a newer correction; never silently rebase it.

**Concrete bounded receipt proof case (new proposal):** A corrects frames `[20,40)`, commits receipt A, and its HTTP response is lost. Another explicit view then commits correction B to `[25,35)` on the same target, replacing the single receipt with B. A delayed retry of the exact A request sees that its ID is no longer the latest receipt and its submitted prior_correction_id no longer equals B (and its original affected baseline may also be stale): return409, preserve all B geometry/keyframes/choices and the client's uncertain A snapshot, and perform no tracker/model work or publication. Do not search for A in histories, reinterpret it as a new request or overwrite B. Even if B is disjoint or happens to produce semantically equal geometry, the prior_correction_id mismatch still gives an explicit conflict; bounded recovery never promises all historical requests can be acknowledged. If B never committed and A is still the current matching receipt/effect under current source/timeline, the retry succeeds without mutation. A client must explicitly reinspect before a new correction after this conflict. This is a contract proof case only; no runtime probe was performed.

No simultaneous corrections are required: existing one-tracker-per-job gate is sufficient. Independent choices/audio can save during compute and must survive publication. A cancelled operation whose report committed before cancellation can be acknowledged by a later valid receipt replay; cancellation after atomic publication cannot roll back committed data. If cancel won before publication, no receipt/result exists and an explicit fresh launch/retry must pass admission anew. Old statuses/polls cannot repaint a different target/job/editor; use P10 mounted-view and captured-launch checks.

### Raw-index and draft limit that must be implemented

Replacing rows can shift raw indices. Current enabled-only saves have **no context** and can otherwise apply an old click to a different row. P10 geometry context alone does not solve that. Avoid append-only retired full histories merely to preserve indices.

For provenance-capable optional reports that permit retracking, extend every submitted indexed output-choice delta with `choice_context_eq`: canonical equality of that raw row excluding only enabled/output_choice and derived effective display fields. It is row-local and needs no exact image/sample. Validate at the same current raw index under report_lock, with no search/rebind; distinguishable shifts/replacements return409 for the entire combined save. Semantically indistinguishable duplicates share P10's documented limit. A plain stale integer map is rejected in this capability; ordinary/legacy saves stay unchanged. Include row context in the existing deep submitted snapshot. New optional manual creation/replay must use P10's already adopted strict/immutable interfaces.

Before launch the UI saves or retains pending edits under their original contexts; it must not transplant pending raw indices after the resulting review refresh. Successful ACKs clear only submitted matching-context values; newer drafts retain their original row context and conflict safely after layout changes. Existing unrelated audio/choices already committed during compute merge from latest report. Target group choices during gaps use the explicit target interval adapter rather than inventing a representative raw row. This optional adapter is a prerequisite, not a current API. A smaller UI may temporarily disable new indexed editing while its own correction computes, but that is not a server race solution and does not replace context checks for another view. ### Opaque fields: equality is a fence, not preservation

The earlier replacement step's phrase “unknown affected row fields are compared/preserved” needs a concrete restriction: **comparing an opaque field for equality does not preserve it when the entire source row is subsequently deleted.** Neither copying a same-index value into an arbitrary new sample nor retaining all old rows as history is acceptable.

The smallest safe first-delivery rule is an explicit optional-regeneration field ownership table. For every affected generated row that would be removed or rewritten, the adapter must know which fields it regenerates (box/index/timing/offset/method evidence and known optional target reference), which fields it derives from retained target intent (output_choice/enabled), and which it preserves through an explicit semantic mapping to the same frame/keyframe. Known unsupported shape/person/other metadata cannot be dropped merely because the optional engine emits boxes. Unknown top-level report fields and rows outside the replacement remain raw-preserved by the latest-document merge.

**If any field or nested metadata on a row that will be deleted/replaced has no defined regeneration/preservation owner, reject the whole new correction/trim/split replacement before publication.** A current, unchanged but unsupported extension may return `422 unsupported_regeneration_metadata` with its field path; an extension/context added or changed since admission returns409 `target_conflict`. Preserve the complete report and all pending drafts. Validate this once before expensive work and again at publication. A known unchanged protected endpoint row that is retained verbatim needs no invented regeneration rule; replacing that row later is subject to the same gate. Do not infer that every opaque extension is geometry-neutral, normalize it away, transplant it to a lookalike frame, or retain redundant old sample histories to avoid the decision.
