## Root-adopted legacy association distinction

The existing current_source descriptor cannot say whether it originated from an initial no-provenance legacy dict or a successful provenance-bound association. Looking only at current path/stamp/status would permit a formerly bound report to remove provenance and masquerade as legacy, or would unnecessarily deny every repeated legacy read.

Root adopted the smallest extension inside the same owner:

- Add private _JobFiles.source_report_bound=False.
- Extend _select_observed_locked(job,prepared,authoritative=False,*,report_bound=True). All current exact/save/Track/adoption callers use true; the initial tolerant legacy path passes false.
- Set true **only after successful provenance-bound association**, including same-source success; never from a prepared candidate, failed/stale attempt or before authority validation. False never clears true. Pending/retirement/replacement cannot reset it within the incarnation.
- Missing means absent provenance, or a provenance dict with no input key. Malformed means an explicit non-dict provenance (including null), or explicit null/nonstring/empty/whitespace-only input. An explicit invalid input never falls back.
- Initial missing-input legacy selection uses admitted canonical job.video, actual source lease and all ordinary final fences. Repeated same coherent legacy association may stay legacy. A formerly bound report losing input, pending/retired/failed pair, observed source replacement or failed managed adoption stays unavailable. This tolerant association does not prove provenance or new exact readiness.
- Tests cover initial versus bound/pending/retired modes and failed/stale association not poisoning initial mode. If implemented incorrectly, the bit either permits an unsafe provenance downgrade or unnecessarily strands old ordinary reports. It never enters JSON/options/jobs/public URLs.

Actual old-list behavior is not a supported cold thumbnail/timeline path: detections/detframe/cold thumb index dict keys, and rehydrate's .get fails/skips it; old warm thumb2 can bypass those failures. P08A removes that stale bypass and returns a current structured invalid-report500. It does not invent list conversion, dimensions or exact readiness.

## Locked contract and browser boundary

The companion plan pins all helper signatures, request/response fields, error codes, RED/GREEN schedules and command recipes. Key decisions:

- V is opaque uuid4 hex bound to the existing incarnation/source/report/operation owner and opened stamps plus crop/detframe recipe versions. No full-input hashes on cold or warm paths; no retained report tree. Raw-row equality includes the entire unrounded row and differs from exact row_context_eq. Reliable observed replacement is supported; equal-observed-attribute external mutation is not.
- Add only openscrub_internal/thumbnails.py as a production helper; web retains Flask/lifecycle authority. One generation/discovery, four unsettled fills total, one per key, exact reader tickets and one retired cleanup backlog. One-second discovery wait; explicit V never substitutes another generation; unversioned compatibility reselects once.
- GET detections adds thumbnail_version and per-row thumbnail_row. Crop/lightbox use ?v=V; versioned200/304 require private revalidation and strong JPEG-byte ETag **after** current-generation checks. Metadata/unversioned/errors are private/no-store. Pending/adoption/source/invalid-report errors cannot return old JPEG200/304.
- Demand and pregen share the same clamped decode/cum integer and pinned crop recipe. Every successful file is staged0600 and atomically accepted after source/report/operation revalidation; a late producer cannot overwrite the first accepted body. Detached reads revalidate after materialization and close; cancellation after final acceptance cannot recall delivered bytes.
- Retire access before validating replacement. Unlink only owned derivatives outside locks after actual readers close. Three cleanup attempts and one backlog prevent unbounded revision retention; blocked cleanup prevents further disk materialization. Closed/drained vault transition and recovery explicitly evict thumbnail state, including existing JOBS entries. Shared exact source_ref is not reset.
- Ordinary/zone/group/lightbox bindings carry V and real raw index/fingerprint. One coalesced metadata attempt per mounted review, never replenished by patched V/save ACK/error. Patch only equal raw-index bindings (groups also check original member bindings); otherwise retain unavailable status and request explicit reopen. Fence late A→B→A/root/node continuations.
- Recovery never calls loadReview/showPanel/openJob/trimReviewDraft/loadBoxEdit or changes EDITS/REVIEW_DRAFTS/EN/MAN/manual IDs/BE/audio/save/uncertain snapshot owners. Thumbnail V is not source_ref/timeline_eq/row_context_eq/base or a geometry precondition. Choice/audio changes can invalidate V while exact semantic geometry CAS remains valid; a real source conflict retains drafts for reinspection.
