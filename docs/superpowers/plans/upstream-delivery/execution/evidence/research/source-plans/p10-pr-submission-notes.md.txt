## PR 3 — original standalone P16D

**Title:** Keep editor overlays and pointer edits aligned after live resize

**Ready-to-use description:**

Resizing an open editor could leave its canvas and inverse pointer mapping at the previous display size. In the reproduced mobile case, the outline moved 167.8 CSS pixels from the visible target and clicking it missed. A mount-owned transform now updates painting and pointer coordinates together for the active image/video, including fractional sizes and DPR-aware backing dimensions. Resize ends the active gesture while preserving edits already applied, and stale callbacks cannot affect a replacement editor.

The playback check also exposed an existing metadata-loading deadlock. The editor explicitly starts loading when the user presses Play, after installing its metadata listeners, while retaining `preload="none"`. Source/content-coordinate conventions and the existing save/audio ownership remain.

This standalone contribution is based on reviewed P07a browser-save ownership at `9212475` and ends at `47e9f6d`. It does not depend on the exact-sample backend or a combined application branch. Independent spec/quality review approved it.

Validation on this original standalone revision includes an exact-base painted-pixel/hit failure, real PAGE painting and pointer events at desktop/mobile sizes and DPR 1/2, fractional geometry, gesture/stale-callback/playback cases, real save/fresh reopen and decoded SDR output. All 197 discovered tests passed; 74 focused actual Python 3.9 and 74 installed-package checks passed, alongside offline packaging and installed browser acceptance. Maximum measured corrected edge error was 1.023 CSS pixels within a 2-pixel tolerance; rendered output uses a 3 source-pixel raster tolerance.
