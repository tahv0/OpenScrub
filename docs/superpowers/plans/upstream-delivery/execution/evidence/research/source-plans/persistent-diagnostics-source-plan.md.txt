### What, why and scope

Worker failure stage/progress/classification disappears after restart; capturing arbitrary stdout or callback messages would retain access tokens, OCR and path-bearing exceptions. Implement a small stdlib-only `openscrub_internal/diagnostics.py` with narrow existing web lifecycle hooks, tests/test_runtime_logging.py and concise docs/LOGGING.md. Reuse the existing private package distribution paths. Disabled imports/calls create no directories, files, hooks or threads and leave console output unchanged.

1. Follow the research's exact event-specific schema: schema version, internal session/action references, UTC time, known action/stage/outcome/transport/stop/vault/error enums and bounded finite counters only. No free-form message, exception object/class name, traceback, nested dictionary, argv/path/URL/header/token/query/crop/detection/options or serialized stable job ID. Internal job IDs may key an in-memory action lookup but only generated action references leave memory. Do not stringify hostile/unknown objects as validation. Reject unknown kinds/fields/types without persisting their values; maximum encoded event 1 KiB.
2. Emit service_started; admitted job_started; actual stage changes; at most one heartbeat per 60 monotonic seconds per active job; job_finished with a fixed outcome/error classification; existing worker escape/restart facts; and service_stop/validated previous_run_unclean. Counter callbacks update small state without file I/O on every call. Idle service emits no heartbeats. Inactivity is no reported progress, not a hang diagnosis; an unclean marker is no observed clean close, never an OOM diagnosis.
3. Bind each admitted action to its operation-specific local handle so a stale finally/callback cannot finish, overwrite or unregister a newer operation. Start only after existing admission/operation checks, finish/unregister at the existing finally boundary, remove finished state promptly and never retain job objects. Add no alternative worker/watchdog implementation or job-file lease. Preserve existing queue generation, cancellation, native exception and watchdog behavior.
4. Use service-level `_data_root()/logs` outside JOBS_DIR and vault encryption. Explicitly document that sanitized records survive job deletion/vault lock until rotation/manual removal, with no durable job link. `runtime.jsonl` is at most 5 MiB plus exactly two backups; pre-encode/cap and rotate before exceeding the limit. Bound the atomic running marker and its temporary file to 1 KiB each; no fault dump. Permissions 0700/0600 where supported; do not claim Windows ACL validation from Linux.
5. Acquire exclusive service-writer ownership before inspecting/replacing the previous marker or rotating. A second live writer disables its own diagnostics instead of touching the owner's files. Keep lock metadata bounded and use the smallest standard-platform mechanism, not a process-coordination framework. Validate bounded old marker input and derive only approved fields; never echo arbitrary old JSON. Remove the marker only after observed orderly close and successful final write/flush; storage failure may retain uncertainty. No fsync/crash durability promise.
6. Configure after argument parsing and before startup work. Integrate shutdown in the existing owner: vault work precedes diagnostic close; SIGTERM closes before existing os._exit; second-signal behavior stays intact. Preserve `_serve` and known TLS suppression. No new job/file-lock joins or lock-order inversion. Startup/serve failure may leave the marker; retain existing stderr behavior without copying it into the sink.
7. Open/permission/full-disk/rotation/flush/marker/monitor failures disable that sink and cannot escape into scanning, saving, cleanup or worker survival. At most one fixed path-free diagnostic-unavailable console notice per minute; no recursive logging, busy retries or unbounded queue. Close is idempotent and releases writer ownership. Treat partial records/abrupt termination as best-effort evidence rather than inventing a successful finish.
