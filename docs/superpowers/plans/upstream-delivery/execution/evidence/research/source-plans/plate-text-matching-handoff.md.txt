## Proposed semantic decisions and tradeoffs

1. Full is normalized string equality, including all supplied candidate text. XABC123Y does not equal full ABC123. This intentionally differs from donor "exact" containment.
2. Fragment is explicitly requested and matches the entire 3..16-character literal query contiguously within one normalized observation. It never infers a fragment of a full query and never uses O/0, I/1, regex, edit distance or half-target heuristics.
3. Query errors raise ValueError atomically; unusable observed OCR text yields no match. That reflects user-controlled validation versus imperfect recognized input. Unicode and punctuation are rejected before normalization, not transliterated or deleted.
4. Stable first-occurrence query ordering/dedup is retained; all matching queries are returned. Different modes remain separate pairs. Observation evidence is never deduplicated by literal text.
5. Default dataclass reprs hide query text, observed/normalized text and the original candidate mapping via repr=False. Validation errors contain fixed rule descriptions, not raw/normalized query or candidate values; the module emits no logs or output. No numeric match_strength/target_coverage is retained. Existing OCR scores are untouched opaque evidence, separate from deterministic relation, physical identity and mask support.
6. Space/tab/dot/hyphen removal is supported inside a single candidate observation. The helper never joins separate observations; safe spatial grouping is a future adapter responsibility. A literal matcher cannot establish whether two words grouped by a caller are related.
7. A complete original candidate mapping is returned by reference in each ObservationMatch. No text offsets or substring mask are returned. Mapping fields such as candidate/protection geometry and OCR score are opaque and unchanged. With absent geometry, it still reports only a text relation.
8. A full_frame_text/text_contour mapping is not rejected for origin or absent detector boxes. This removes a pure acceptance barrier without claiming recognition/discovery accuracy for detached plates.
9. New full_equal/fragment results are deliberately not a legacy exact/partial schema. No legacy app/report consumer exists on accepted6fde for this dormant helper; later O03 integration must adapt intentionally and preserve old report behavior.
10. Direct PlateQuery construction and prepared-batch matching are validated, so a caller cannot obtain an accidental fuzzy/empty match by bypassing normalize_queries. Mixed modes can pass through the future unchanged search_frame hints parameter as prepared query objects.

These are proposed extraction corrections grounded in O03 and donor behavior, not newly discovered accepted application semantics. No user-approval pause is required; root reviews/adopts them before coding.
