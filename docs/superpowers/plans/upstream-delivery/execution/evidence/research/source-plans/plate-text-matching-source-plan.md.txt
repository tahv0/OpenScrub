## Exact footprint and interfaces

Add only openscrub_internal/plate_search/__init__.py (inert docstring), openscrub_internal/plate_search/matching.py and tests/test_plate_text_matching.py. Preserve every existing tracked source/default/schema/import/dependency/package/version file byte-for-byte. No jobs.py, worker.py, app/UI hooks or feature guide.

Use Python3.9-compatible frozen dataclasses and typing; stdlib imports only. No slots=True or newer runtime API. Public data:
- MatchMode = Literal["full", "fragment"].
- PlateQuery(text: str, mode: MatchMode = "full"): __post_init__ validates/normalizes individual text and mode, storing normalized text. text uses field(repr=False).
- TextMatch(query: PlateQuery, observed_text: str, normalized_observed: str, match_kind: Literal["full_equal", "fragment"]): frozen result; both text fields use repr=False.
- ObservationMatch(observation: Mapping[str, object], text_match: TextMatch): original mapping retained by identity; observation uses repr=False. Nested evidence stays caller-owned, with no lifetime/thread-safety guarantee.

Public functions:
    normalize_queries(value: Union[str, List[str], Tuple[str, ...]], *,
                      mode: MatchMode = "full") -> Tuple[PlateQuery, ...]
    match_text(observed: object,
               queries: Union[List[PlateQuery], Tuple[PlateQuery, ...]]) -> Tuple[TextMatch, ...]
    match_observation(observation: object,
                      queries: Union[List[PlateQuery], Tuple[PlateQuery, ...]]) -> Tuple[ObservationMatch, ...]

Private helpers:
    _normalize_query_text(value: object) -> str
    _normalize_observed_text(value: object) -> Optional[str]
    _validated_queries(value: object) -> Tuple[PlateQuery, ...]

No legacy normalize_hints alias or exact/partial dictionary shim. normalize_queries prepares one uniform-mode batch. Mixed-mode callers combine prepared batches; matching validates the combined list/tuple, at most ten entries before deduplication. Direct PlateQuery construction also validates, and prepared-query invariants are rechecked before matching.

## Bounded new query contract

This deliberately uses the donor's 3..16 policy as a new explicit contract, not legacy matcher compatibility:
- Supported originals: ASCII A-Z, a-z, 0-9 plus only space U+0020, TAB U+0009, dot U+002E and hyphen-minus U+002D. Validate before uppercasing; delete those four separators and uppercase ASCII.
- Each query: 3..16 normalized literal characters, at most 128 raw Python string characters.
- normalize_queries accepts string or list/tuple of strings only. String batch delimiters are comma, semicolon, CR and LF, split on one-or-more. Drop only empty/ASCII-space-or-tab-only split fields. Unicode-only whitespace is unsupported and rejected. List entries are individual queries; delimiters and empty entries are invalid.
- String payload including delimiters is at most 1024 characters. List/tuple summed raw lengths are at most 1024. Require 1..10 nonempty fields before deduplication; eleven duplicates fail.
- Direct PlateQuery accepts one individual query and never splits delimiters. mode must be exactly full or fragment.
- Stable first-occurrence deduplication key is (mode, normalized text); same literal in different modes retains both semantics/order.
- All malformed/unsupported/empty/short/overlong/oversized queries raise ValueError atomically. Errors describe rules, without embedding raw or normalized query/candidate text. No silent skipping, transliteration, Unicode casefold/normalization, regex/fuzzy/O0/I1 correction.

Examples: "ab-c 123; XY987\nABC123" prepares full ABC123, full XY987; ["BC1"] with mode fragment prepares fragment BC1. AB/123, ÅBC123, ß, Unicode dashes/full-width characters/NBSP, A1 and regex operators are rejected.

## Observation and result contract

One observation represents one already-associated candidate text region. Never join separate tokens, mappings, lines, regions, views or frames. Supported separators within one supplied region normalize as above; grouping unrelated words into that region is forbidden at the future adapter boundary. Literal code cannot infer spatial association.

Observed values must be strings of at most 512 raw characters using the same supported alphabet/separators. Empty/separator-only/<3 normalized characters, unsupported/non-string/malformed/oversized values return (). Do not str()-coerce, truncate or strip unknown characters. Query validation always occurs first.

For each unique query, in first-query order:
- full emits iff normalized_observed == query.text; match_kind is full_equal.
- fragment emits iff the entire literal query.text occurs contiguously in normalized_observed; match_kind stays fragment even when both strings equal.
- Emit all matching queries once each, irrespective of repeated occurrence. Never infer a fragment of a full query, compute longest-common-substring/half-target matches, rank a winner or assign a score.

Thus ab-c 123 equals full ABC123; XABC123Y does not. Explicit fragment ABC123 matches XABC123Y. BC123 does not match full ABC1234; fragment BC1 matches BC123. ABO1/AB01 and ABI/AB1 stay distinct. ABC/123 is unusable observed text.

match_observation accepts any Mapping with usable "text", after validating queries. Missing/invalid mapping/text returns (). All other fields are opaque. Each result wraps the identical original mapping and its TextMatch, without mutation/copying away evidence, adding/narrowing geometry or requiring a source/vehicle/YOLO box. full_frame_text/text_contour origin is not a rejection reason. Complete supplied candidate/protection/text geometry and OCR scores survive unchanged; absent geometry is not manufactured.

No score/coverage, identity, mask confidence, enabled/blur output or report schema. No logging, persistence/cache/registry, filesystem/process/model/video/network work. Default reprs and validation errors exclude raw and normalized query/candidate text; no custom formatting should expose it. Evidence is available only through explicit data fields for a future lifecycle-aware caller.
