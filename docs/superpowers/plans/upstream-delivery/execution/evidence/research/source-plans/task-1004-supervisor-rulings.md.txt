## Explicit conflict recovery without losing other work

Add one `everUncertain` boolean to the existing submitted owner. A first valid, authoritative `409 geometry_conflict`, before any uncertain attempt, proves that request was rejected: release that rejected submission snapshot but keep every pending value/baseline. A network failure, malformed/missing ACK or other unknown publication marks the owner uncertain. Explicit Save retries its identical payload first. A later `409` cannot prove that an earlier uncertain write did not commit, so retain the owner and every draft.

Keep `reviewSaveStatus` text-only. Add sibling `reviewResolveActions` with two bounded actions; do not create another review subsystem.

- **Abandon unconfirmed save…** is available only for an uncertain submitted owner and while no save is busy. Capture the draft/submission, explain that abandoning does not undo possible saved changes, confirm, and recheck ownership. Clear only that retry owner. Keep all current geometry/preconditions, additions/manual IDs, choices, audio and their baselines. Do not POST, acknowledge, undo, advance baselines or render.
- A selector reaches pending position/time rows even when absent from the current frame, with **Discard geometry and inspect**. Refuse while busy or while a submission remains unresolved. Capture the selected draft/editor/view/family and current values before confirmation; recheck all of them afterward. Changed values or ownership abort deletion. Remove only that selected row's captured `ov`, `times` and geometry owner. Preserve other rows, manual additions, choices and audio. End incomplete gestures and request a fresh sample through the existing slot, opening the guarded ordinary editor if necessary. Fresh inspection grants evidence only to a subsequent deliberate edit; never find a similar row, remap a missing row, rebase other drafts or render.

The same selector may list editor-created pending additions as “New box N”, keyed internally by their stable `manual_id`. The same explicit discard action removes only the selected, still-equal captured addition after confirmation; preserve every other addition and `MAN` entry. This provides an escape for stale creation evidence without adding handles or an additions editor. It does not remove a possibly committed report row; resolve or explicitly abandon an uncertain submission first, and inspect the actual saved state.

Required controls: initial authoritative rejection versus uncertain retry rejection; abandon confirmation/no undo/no draft loss; busy/unresolved discard refusal; selected row/addition isolation; changed-during-confirmation retention; fresh inspection without save/render/rebase; absent-row refusal to remap; and deliberate recreation of a discarded stale addition from a new ready sample.

These actions implement the existing explicit reinspection/reapplication requirement. Automatic baseline changes or broad draft resets would lose or misapply work; if this UI choice proves wrong, revise these bounded controls rather than weaken source equality.
