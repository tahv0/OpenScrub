# Bound the active browser job log while preserving reading position

Keeping a job open currently appends browser text indefinitely and replaces the growing transcript on every update. The view now keeps one recent transcript: initial/reset/reopen last 400, then at most 800 callback entries and 2,097,152 represented UTF-16 bytes. Stable content nodes preserve retained selections and reading anchors. Accepted response bodies remain authoritative for cursor progress, including entries omitted from the display.

Scrolling during a pending response is respected. Near-bottom readers follow new output; a scrolled-up reader keeps the surviving entry and pixel offset. If that entry is discarded, the view shows the oldest retained content with a fixed notice. Accepted resets show the recent bottom without moving keyboard focus. View replacement/deletion disposes the resize, scroll and scheduled-frame owners.

Actual producer→HTTP→PAGE tests cover count/text limits, blank and Unicode entries, clipboard/selection ownership, held-body scrolling, the 39/40/41px threshold, narrow/desktop wrapping, offset clamping, replacement/reopen and cleanup. The optional artifact-output convention is corrected in its owning test. A self-contained benchmark recipe ships in the sdist; fresh-root success, child-failure and timeout tests protect its result-writing path.

Validation is bound to explicit source revisions: one full run passed 250 tests before test-only strengthening; subsequent browser 6, actual Python 3.9 owning 59 and installed 54 checks passed at unchanged runtime. Offline sdist→wheel, exact inclusion, updater delivery, installed CLI/defaults and actual Cheroot/browser checks passed. The review fix adds three focused checks on each Python 3.12/3.9 and exact package verification; the rebuilt runtime wheel is byte-identical. [Verification and revision boundaries](../evidence/delivery/task-1203-report.md), [fix evidence](../evidence/delivery/task-1203-fix1-report.md) and [final review](../evidence/delivery/task-1203-fix1-review.md).

The dense 8,192-unit/255-LF fixture still exceeds the declared 16 ms median/50 ms empirical-p95 layout targets: 44.8/66.0 ms, maximum 82.8 ms, with 30 overlapping long tasks. Other tested publication cases meet those targets. All four initial display costs increased: 3.0→6.6, 9.0→12.1, 13.2→14.7 and39.9→42.7 ms. These are retained limitations. Different retained histories and fixed source order do not establish equal-work or universal speed gains; idle wheel checks do not measure input latency during publication. Text/node accounting is not a browser-memory limit. Native suspension and other browser/platform execution remain unverified.
