# Keep editor overlays and pointer edits aligned after resize

Resizing an open editor could leave its canvas and pointer mapping at the previous display size. In the reproduced mobile case, the outline was 167.8 CSS pixels away from the visible target and clicking the target missed. A mount-owned transform now updates painting and pointer coordinates together for the active image or video, including fractional sizes and high-density displays. Resize ends an active gesture while preserving edits already applied; stale callbacks cannot affect a replacement editor.

The playback check also exposed an existing metadata-loading deadlock. The editor now explicitly loads video when the user presses Play, after installing its metadata listeners. The existing `preload="none"` behavior remains in place.

Validation includes actual page pixels and pointer events at desktop/mobile sizes and DPR 1/2, source-coordinate save and fresh reopen, and decoded SDR output. The final regression fails on the exact prerequisite; all 197 discovered tests pass on the candidate, along with 74 focused Python 3.9 checks, 74 installed-package checks, offline packaging and installed browser acceptance. Corrected measured edge error is at most 1.023 CSS pixels within a 2-pixel stroke/raster tolerance.
